# 前端管理页面 UI 设计（参照 Hermes Agent Dashboard）

日期：2026-10-18　状态：UI 已确认；交付方式待定（见第 11 节），定了再写实现计划
原型图：`docs/specs/assets/2026-10-18-frontend-admin-ui/`（浏览器直接打开；01 是导航三选一的过程稿，最终选 A；02 中只采用对话页，知识库与用量两张图不采用）

## 1. 目的与背景

对话页是最常用的页面，但模型、技能、MCP、系统这些"管理"工作目前要靠改 yaml、敲 make、看 docker 日志。目标是参照 Hermes Agent Dashboard 的"模型 / 技能 / MCP / 配置 / System"页面，在个人智能体里补上这几页，**既能看状态，也能直接改**。

本文只定 **UI**（页面结构、交互、规则）。后端接口与实现留到功能阶段，第 9 节列出了功能阶段必须先决策的冲突点。

**为什么学 Hermes**：用户喜欢它的管理页面设计；项目的主题色本来就照 Hermes 定（深青 `#041c1c` + 奶油色 `#ffe6cb`，见 D16、设计文档 §13.2），所以是搬页面结构，不是换皮。

## 2. 目标 / 非目标 / 反目标

**目标**
- 新增页面：模型、技能、MCP（配置页见非目标）。
- 系统页、日志页：UI 已定（第 8 节），**放到下一轮**再实现（用户决定）。
- 对话页和所有新页面使用同一套页面骨架。
- 会话列表从左侧栏移进对话页，成为对话页的第二栏。

**非目标（本次不做）**
- 配置页：用户还在思考范围，暂不设计。现有"设置"页暂时保留，等配置页定了再拆。
- 技能的在线编辑、从官方技能库导入（R22 的后半，保留在需求池）。
- 左侧栏底部的状态块（Hermes 有，用户明确先不要）。
- 知识库、用量两页改成新骨架：保持现状，只随左侧栏一起变化（用户决定）。
- MCP 目录的分类按钮。

**反目标（做成这样就算失败）**
- 左侧栏变成 Hermes 的翻版：要保留个人智能体现有侧栏的功能，只**新增**需要的入口。
- 不经确认的破坏性操作：删除、恢复、对话里装技能都必须先确认。

## 3. 整体框架

### 3.1 左侧栏
- 保留现有内容（"PERSONAL AGENT" 品牌字、知识库、用量、明暗切换等），**移除会话列表**（移到对话页）。
- 新增入口，分两组，中间留间隔：
  - 工作：对话、知识库、用量
  - 管理：模型、技能、MCP、配置（暂不做，入口是否先放由实现计划定）、系统、日志
- 选中项：浅色底 + 左侧竖线（原型 02）。
- 底部不加 Hermes 的状态块。

### 3.2 路由
每页一个真实地址（`/chat/:会话ID`、`/knowledge`、`/usage`、`/models`、`/skills`、`/mcp`、`/system`、`/logs`），刷新和收藏能回到原页；对话页地址带会话 ID，刷新后回到同一会话，ID 无效或会话已删时回到 `/chat` 空状态（Claude 的判断）。现在 `AppShell` 用 `useState` 切页，需要引入路由（选型由实现计划定）。

### 3.3 统一页面骨架（对话页 + 新页面；知识库、用量不改）
- 顶部标题栏：左边页面名，右边放搜索或主操作按钮。
- 内容区：直角细边框卡片，区块标题用等宽字体、字距稍宽。
- 按钮：描边、大写的小按钮；主操作用实心奶油色。
- 长文（对话内容、记忆文字、SKILL.md 正文）仍用中文无衬线体。
- 颜色只用现有令牌（`tokens.css`），遵守 `no-raw-colors` 测试。

## 4. 对话页（统一骨架，原型 02 上半）

**对话页**
- 第二栏是会话列表：顶部"+ 新建"和折叠按钮，可折叠让对话区更宽；现有的重命名、删除、拖拽排序全部保留。
- 标题栏：会话名、token 用量、模型下拉。**切换模型保持现有方式**（按会话切换）。
- 消息区、输入框、审批卡片基本不变。
- 原型里会话按"今天 / 本周"分组是 Claude 加的，现有列表没有分组，实现时可去掉。

**知识库、用量**：保持现有页面样式不变（原型 02 下半的两张图不采用）。

## 5. 模型页（原型 03）

- 标题栏：模型数量；右侧"重载网关"（相当于 `make restart-gateway`）和"+ 新增模型"。
- **默认模型卡**：对话模型、向量模型两个下拉框，选了就生效（对应 `app.yaml` 的 `agent.default_model`、`knowledge.embedding_model`）。这里只改新会话的起点。
- **已登记模型清单**：每行显示名称、来源、上下文与输出上限、价格（未填写"价格未填"）、能力标签（思考 / 看图 / 工具 / 向量），默认模型带"默认"标签；右侧"测试 / 编辑 / 删除"。
- **测试**：结果显示在该行（如"✓ 可用 · 820ms"，失败显示原因）。
- **新增 / 编辑**：右侧抽屉，一张表单填完（用户选了抽屉，没选两步向导）。字段：来源、厂商模型 ID、显示名、类型（对话 / 向量）、能力、上下文 / 输出上限与价格（先自动查，可手改）。底部"测试连接"和"保存并重载"；编辑时左下多一个"删除"。
- **删除**（确认框）：说明会从 `models.yaml` 移除并重载网关；如有会话在用，提示"有 N 个会话正在用它，之后会改用默认模型"；历史消息和用量保留。
- 规则（用户已确认）：
  - 默认模型不能删，删除按钮置灰，悬停提示"先换掉默认再删"。
  - 被删模型的会话自动改用默认对话模型。
- 不做"模型来源"卡（用户删掉了）。

## 6. 技能页（原型 04）

- 标题栏：已启用数 / 总数；搜索框；"↑ 上传技能"。
- 左侧筛选：全部 / 已启用 / 已停用。**不显示来源**（用户删掉了来源筛选和来源标签）。
- 列表每行：开关、名称、一句描述、"查看"。停用的行变暗。
- **查看**（右侧只读抽屉）：顶部开关；描述、存放位置、添加时间；"SKILL.md"标签页渲染正文，"文件"标签页列出所有文件；底部"删除技能"。
- **上传**（对话框）：可拖入或选择**技能文件夹 / .zip / 单个 SKILL.md**；文件夹或压缩包里必须包含 SKILL.md。先识别出名称、描述、文件数，再点"安装"；同名时提示"安装将覆盖它"。
- **在对话里添加**：用户在对话里发一个技能文件夹 / zip / SKILL.md 并要求加成技能，智能体弹出确认卡片（样式同现有审批卡片），按钮"查看内容 / 取消 / 安装"。
- 规则（用户已确认）：
  - 停用 = 智能体暂时看不到它，文件保留。
  - 上传的和对话添加的技能可删；项目自带的不显示删除按钮（来源不展示，但内部要记）。
  - 对话里添加必须经用户确认。
- 不做：编辑技能、从官方技能库导入。

## 7. MCP 页（原型 05）

- 标题栏：右侧"重新加载"和"+ 手动添加"。
- **我的 MCP 服务**：每行开关、名称、描述、类型（本地进程 / 网络）、工具数、状态（已连接 / 出错 + 原因 / 已停用），右侧"查看工具 / 编辑"。
- **目录**：搜索框 + 卡片网格（**不要分类按钮**）。每张卡标类型和"需要密钥"，右侧"安装"；已装的显示"已安装"。用户最常用的添加方式就是从目录点安装。
- **从目录安装**（对话框）：只问必填项（如 API 密钥、服务名），"测试连接 / 安装并连接"。
- **查看工具**（右侧抽屉）：启动命令、未写规则时的默认行为；每个工具一行，带"只读"标签和"自动 / 先问"切换（即 `approval_rules.yaml` 按工具的规则搬到界面上）。
- **手动添加**（右侧抽屉）：三个标签页：本地进程（命令、参数、环境变量）、网络地址（地址、请求头）、粘贴 JSON（识别常见的 `{"mcpServers": …}`）。底部"测试连接 / 保存并连接"。
- 规则（用户已确认）：
  - 按工具的审批规则放在"查看工具"抽屉里。
  - 页面填的密钥写进 `.env`，之后只显示末 4 位。
  - 目录是项目自带的挑选清单，不联网拉取。
  - 停用服务 = 断开连接，配置保留。

## 8. 系统页与日志页（原型 06）

> 放到下一轮实现（用户 2026-10-18 决定）：两页都依赖第 9 节第 4 条的 Docker 控制权。UI 先定在这里，本轮侧栏是否先放入口由实现计划定。

**系统页**（把"看 docker 日志、敲 make"搬到页面上）
- 标题栏：上次检查时间、"刷新"。
- **服务状态**：每个容器一张卡（后端、PostgreSQL、LiteLLM 网关、Ollama）+ 一张 MCP 汇总卡。显示状态、已运行时长、CPU / 内存（数据库显示库大小，网关显示已加载模型数）；出问题时边框变红并写原因（如"退出码 137（内存不足）"）。卡片下方"日志"和"重启"（网关是"重载"，已退出的是"启动"；MCP 卡是"去 MCP 页"）。
- **常用操作**（对应 make）：重启后端 `make restart`、重载网关 `make restart-gateway`、重新构建并启动 `make build`、数据库迁移 `make migrate`；每行写命令和适用场景，右侧"执行"。
- **备份与恢复**：最近 7 份（时间、自动 / 手动、大小），"立即备份"，每份可"恢复"。
- **本机信息**：版本、数据目录大小、磁盘占用、Docker 版本。
- **恢复确认框**：恢复前自动备份当前数据；进行中的对话会被打断；`config/` 与 `.env` 不在备份里。
- 规则（用户已确认）：
  - 常用操作只放上面 4 条；`make down`、`make install`、`make check` 不放。
  - 恢复只能从列出的备份里选。

**日志页**（侧栏独立入口，放在"系统"下面）
- 效果类似 `docker logs -f`：按容器切换、只看错误、搜索、"实时跟随"开关；警告黄、错误红。
- 侧栏进入默认显示后端日志；从系统页某张卡点"日志"，跳到日志页并选中该容器。

## 9. 功能阶段必须先决策的冲突点（按 CLAUDE.md"需求先核对"）

UI 本身不受影响，但下列"能直接改"的功能与现有部署冲突，写实现计划前要先定方案（可能需要决策记录）。**2026-10-18 已定，见 D21**（交付方式 C）。

1. **配置目录是只读挂载**：`docker-compose.yml` 里后端挂载 `../config:/app/config:ro`。模型页改 `models.yaml` / `app.yaml`、MCP 页改 `mcp_servers.yaml` / `approval_rules.yaml` 都需要写权限。
2. **技能目录是只读挂载**：`../agents:/app/agents:ro`，技能在 `agents/skills/`。上传、删除、停用技能需要一个可写位置（例如放到 `workdata/` 下），以及记录"停用""来源"的地方。
3. **密钥写 `.env`**：后端容器通过 compose 的 `environment` / `env_file` 拿环境变量，没有挂载 `.env` 文件；`mcp_servers.yaml` 注释还要求新密钥在 compose 的 `backend.environment` 里显式传入。页面写 `.env` 后要让进程拿到新值，需要重建容器或换一种传递方式。
4. **系统页控制 docker / 执行 make**：后端在容器里，目前没有 Docker 控制权。可选方案：挂载 docker.sock（等于给后端宿主机权限，与 §12.2 安全防护有冲突），或在宿主机另跑一个只接受白名单命令的小助手进程。还要处理"重启后端"时后端自己被重启的问题。
5. **重载网关**：网关挂载 `models.yaml:ro`，现在靠 `make restart-gateway` 重启容器，同样依赖第 4 条。

## 10. 留给实现阶段的事

- 路由库选型、目录结构、组件拆分（遵守 dev-standards 与现有 shadcn 风格手写组件）。
- 各页需要的后端接口（现在只有模型、技能、MCP、审批的只读接口，以及 `/health`）。
- MCP 目录清单的具体内容与存放格式。
- 模型信息"自动查询"的来源（网关返回 / 内置表）。
- 配置入口在配置页设计好之前是否先显示。
- 现有"设置"页的去留（等配置页）。

## 11. 交付方式（待用户决定，决定前不写代码）

写实现计划前，先由用户从下面三种里选一种。三种工作量差一个数量级，计划完全不同：

| 方式 | 做什么 | 计划里要额外处理的 |
|---|---|---|
| A. 纯界面 | 每页用假数据，能点能看，不连后端 | 假数据层放哪里；`make check` / e2e 怎么对待它 |
| B. 能读的接上 | 显示用现有只读接口（`/api/models`、`/api/settings/skills`、`/api/settings/mcp-servers`、`/api/settings/approval-rules`、`/health`）的真实数据；修改类控件先置灰 | 逐页列出本轮不可用的控件及其表示方式（置灰 / "即将推出"） |
| C. 一起做完 | 读写都接上 | 先为第 9 节的冲突写决策记录；计划里拆出后端任务 |

另一个待定项：技能页的"在对话里添加"（确认卡片）需要改智能体和事件流，不只是界面；放进哪一轮随交付方式一起定。
