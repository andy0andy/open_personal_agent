# 第一轮优化设计（2026-10-19）

状态：已确认（2026-10-19）；三批写成一份实现计划 `docs/plans/2026-10-19-optimization-round1.md`　来源：`docs/reviews/2026-10-19-功能梳理与优化建议.md` 与用户 2026-10-19 的意见

## 1. 为什么做

v1 功能齐了，但用起来有几处别扭：会话里换的模型不保存、审批卡片太多又看不清、预算刹车用处不大、配置散在 `config/` 和 `workdata/config/` 两处还要"叠加"、本机安全防护和令牌暂时用不上、用量数字对不上。这一轮按用户的意见把这些理顺，让日常使用更顺手，结构也更简单。

## 2. 目标、非目标、反目标

**目标**
- 每个会话有自己的审批权限档位，最高一档跳过所有审批。
- 输入框下面一行放齐常用控件：权限、用量、模型、文件；会话里换的模型存下来。
- 去掉按调用次数的预算刹车；模型额度用完或调用失败时，已输出的部分保留，说"继续"能接着做。
- 配置只有一个来源：普通设置在数据库里，技能、MCP 服务清单、审批规则在 `.workdata/` 里；不再有"自带 + 用户"的叠加。
- 删掉本机安全防护（令牌、主机名与来源检查、只收 JSON）和 MCP 目录。
- 用量只算两个数：实际发给模型的输入、模型的输出；后台不再算费用，但每个模型都有价格字段。

**非目标**（本轮不做）
- 换向量模型、提升检索质量（已在审视文档里回答，留到以后）。
- 信任边界（D22 设想）与命令写入范围限制（R33）。
- 审视文档第 4 节里不在下面清单中的其他优化项。

**反目标**（做成这样就算失败）
- 你现有的会话、记忆、文档、上传过的技能、加过的 MCP 服务、页面加的模型，在迁移或改名后丢了或悄悄变了。
- 改了设置不知道有没有生效、要不要重启。
- 安全上的取舍没写下来——以后看不出当初为什么这样。

## 3. 用户已定的（2026-10-19）

| 事项 | 用户的决定 |
|---|---|
| 审批权限 | 每个会话在输入框下方选权限，最高一档跳过所有审批；**三档** |
| 预算刹车 | 不要；模型额度用完就暂停并提示 |
| 输入区 | 右上角的会话用量、模型选择、文件挪到输入框右下角，与权限同一行；样式按现有风格自行设计 |

| 配置 | 去掉叠加；技能、MCP 只从数据目录加载；`workdata` 改名为 `.workdata`；`config/` 里的设置改到 PostgreSQL 管理，在设置页展示；加载时先读数据库，再用同名环境变量覆盖 |

| 用量 | 只统计实际发给模型的全部输入（含命中缓存的部分）和输出；后台不算费用；每个模型都要有价格字段 |

## 4. 设计

### 4.1 会话的审批权限（三档）

| 档位 | 名称 | 行为 |
|---|---|---|
| `ask`（新会话默认） | 每次先问 | 现在的做法：执行命令先问；外部工具按审批规则（服务声明只读的自动，其余按 `mcp_default`，默认先问）；内置的读写会话文件等自动 |
| `ask_execute` | 只问执行命令 | 只有执行命令先问，其余全部自动（审批规则不看） |
| `skip` | 跳过所有审批 | 什么都不问，包括执行命令 |

- 档位存在会话上（`threads` 加一列），新会话为 `ask`。
- **一次运行开始时定下档位，整次运行（含审批后继续）都用它**；运行中或等待审批时改档位，从下一条消息起生效，选择框旁边提示一句（我的决定：运行中途改变中断点会让审批核对失效，代价大于收益）。
- "执行命令固定先问"（D21 第 7 条）只在 `skip` 档位下放开，前两档照旧。
- 外部工具的审批规则仍在 MCP 页按工具设置，只在 `ask` 档位起作用；MCP 页写明这一点。

### 4.2 输入区改版

- 对话页顶栏只留会话标题。
- 输入框下面加一行工具条（在输入框外、紧贴下沿）：
  - **左边**：权限选择。样式参考 Claude Code：一个小标签按钮显示当前档位，点开是带标题和一行说明的列表，当前项打勾；`只问执行命令` 用警示色、`跳过所有审批` 用危险色，让人一眼看出风险。
  - **右边**：会话用量（token）· 模型选择 · 文件按钮（打开右侧文件面板）。
- 模型选择改为**存到会话上**：一改就保存；下一条消息用它；刷新、切页后不变。删模型后会话改用默认模型（现有逻辑）照常生效。
- 窄屏时右边的控件可以收成图标（实现时定细节）。

### 4.3 去掉预算刹车；额度用完时提示

- 删除按调用次数的预算刹车：`budget` 设置、暂停与"继续 / 停止"卡片、推送的预算状态、恢复时的预算参数、设置页的预算展示。
- 模型服务返回"额度用完"（余额不足、配额耗尽一类的报错）时：这次运行结束，显示一句中文原因（"模型额度用完了……充值后说'继续'接着做"），已输出的部分保留（见 4.4）。不另设一个"暂停"状态（我的决定：用户充值的时间不确定，挂着一个暂停的运行没有意义；保留已输出部分 + 说"继续"效果相同）。
- 历史记录里旧的预算暂停卡片照常能打开，显示为一段说明文字，不再有按钮。

### 4.4 失败与额度用完时保留已输出部分

- 运行失败（含额度用完、上游报错）时，像点"停止"一样把已输出的部分连同一句中断说明写进对话存档；说明写清实际原因（不是"用户停止"）。
- 下一句说"继续"时模型知道自己写到哪里。

### 4.5 上传上限统一为 50MB

- 一个设置项（50MB）同时管：对话附件、知识库文档、技能包。
- 单张图片 5MB 是模型厂商的限制，不变；文件预览的上限（表格 20MB、文字 1MB）是显示用的，不变。

### 4.6 修复：数据分析员读不到技能

- 自定义子智能体与通用子智能体一样拿到技能来源；`data_analyst.md` 去掉写死的路径。

### 4.7 配置：数据库 + `.workdata`，去掉叠加

**普通设置进数据库**
- 现在 `config/app.yaml` 里的设置（各可替换接口选用的实现、命令时限、上传上限、默认对话模型、模型卡住时限、向量模型、知识库的召回与切块参数、模型来源）改存数据库的一张设置表；`config/app.yaml` 删除。
- 取值顺序：**代码里的默认值 → 数据库 → 环境变量（同名，含 `.env`）**，后者覆盖前者。必须在连数据库之前就知道的（数据库地址、网关地址与密钥、`LITELLM_SALT_KEY`）只在环境变量里，不进数据库。
- **让 `.env` 里的同名变量在容器里真的生效**（我的决定）：后端容器整份读入 `.env`（现在只转发几个变量，后端看不到 `.env` 里别的内容）。智能体执行命令时仍只传白名单里的环境变量（D20），命令看不到这些密钥。改了 `.env` 要重建容器才生效：`make restart` 改为重建后端容器（不再用只重启进程的做法），设置页的提示也照此写。
- "模型来源"在设置页只读（我的决定：来源里有网关地址，能改就可能把密钥发到别处）。
- 设置页列出全部设置：当前值、来源（默认 / 数据库 / 环境变量）、能否在页面上改（被环境变量覆盖的不能改）、改了是**立即生效**还是**重启后端生效**。第一版只有"默认对话模型"立即生效，其余标"重启后生效（终端执行 `make restart`）"；向量模型只读。

**`.workdata/` 是唯一的数据目录**
- 目录名从 `workdata` 改为 `.workdata`（项目根目录下；容器里的路径同步改名）。
- 结构：
  - `config/mcp_servers.yaml`（MCP 服务清单）、`config/approval_rules.yaml`（审批规则）、`config/skills.yaml`（停用了哪些技能）；
  - `skills/`（全部技能）；
  - `workspace/`、`knowledge/`、`shared/`、`cache/`、`backups/`（同现在）。
- 去掉叠加：`config/mcp_servers.yaml`、`config/approval_rules.yaml`、`config/mcp_catalog.yaml`、`agents/skills/` 不再被加载；"自带"的说法在三个管理页上去掉，全部条目都能改、能删。
- **首次启动写入默认内容**（数据目录或数据库里没有时才写，之后不再覆盖）：默认的 `files` 服务、默认审批规则、`excel` 技能。种子文件放在仓库里一个只用于首次写入的位置（如 `deploy/seed/`）。
- **模型**：`config/models.yaml` 里现有的 4 个模型，首次启动时经网关接口导入网关数据库；之后 `models.yaml` 只留网关自身的设置，模型全部在网关数据库里、全部能改能删。导入时补齐 gemini、gpt 的上下文长度、看图能力与价格。
- **迁移现有数据**：停掉服务后把 `workdata/` 改名为 `.workdata/`；`workdata/config/` 里已有的用户改动（MCP 服务、审批规则、默认模型、技能停用）合并进新位置；之前页面加的模型本来就在网关数据库里，不动。这一步执行前再向用户确认一次。
- **退回办法**（我的决定）：没有 git，代码改了退不回去。第二批动手前，把整个项目（代码 + `workdata/` + 两个数据库的导出）打包成一份整体快照，出问题时用它整体退回旧版；迁移后的新代码不支持恢复迁移前的旧备份（`make restore` 认出旧格式时拒绝并说明原因）。

**设置页改版**
- 去掉"审批规则与预算"；外观、技能、MCP 状态等与三个管理页重复的内容也去掉。
- 保留：外观（明暗切换只留这一处或侧栏一处，实现时定）、上面的设置列表、`.workdata` 下各文件的位置与状态（写坏时显示原因）。

### 4.8 删除本机安全防护

- 删除：访问令牌与令牌页、局域网访问（`LISTEN_ADDRESS`）、主机名白名单、写操作来源检查、只收 JSON、启动时的配置自检里与这些相关的部分。
- 端口固定只绑本机 `127.0.0.1:8000`（局域网访问随之取消）。
- **风险（用户 2026-10-19 两次确认后接受）**：删掉以后，**你浏览的任何网页都能在本机执行任意命令，与会话的权限档位无关**：
  - 网页能直接调后端接口：把会话档位改成"跳过所有审批"、替你点"同意"（`/runs/{id}/resume`）；
  - 更直接的是 MCP 的"添加服务""测试连接"：提交一个本地进程型服务、命令随便写，后端立刻以 root 身份运行，完全不经过审批；
  - 主机名检查没了以后，"DNS 重绑定"（让恶意域名指向本机）也能调全部接口；新版 Chrome 访问本机前会先弹窗请求许可，能挡掉一部分，但不能依赖。
  - 以后由第三方防护补上。D23 如实写下这些。

### 4.9 去掉 MCP 目录

- 删除 MCP 页的"目录"一块与 `config/mcp_catalog.yaml`、目录接口；保留"我的 MCP 服务"、手动添加、粘贴 JSON、测试连接。

### 4.10 备份（我的决定：保留）

- 理由：已做好、有测试，几乎没有维护成本；设置进数据库后，数据库更值得备份。
- 随改名：备份放 `.workdata/backups/`；范围是两个数据库 + `.workdata` 的 `config/`、`skills/`、`workspace/`、`knowledge/`、`shared/`。
- 如果你仍想删掉，告诉我即可（删掉 `make backup/restore`、两个脚本与测试）。

### 4.11 用量口径

- 只有两个数：**输入**（实际发给模型的全部输入，含命中缓存的部分）、**输出**。用量页、每轮页脚、输入框旁的会话累计都用这一个口径；不再单列"缓存"。
- 后台不再计算、存储、返回费用；网关算出的费用也不读。
- 每个模型都有价格字段（美元 / 每百万 token，可以是免费）：模型页必填；导入的 4 个自带模型补齐价格。价格只是模型的资料，不参与任何统计。
- 标题生成、记忆整理、向量化这些后台调用照常计入（它们也是真实调用），用量页按"调用方"分开显示；会话累计包含它们（我的决定）。
