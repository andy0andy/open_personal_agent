# 个人智能体与 Hermes Agent 对比（2026-10-20）

- 对比对象：Hermes Agent（Nous Research 开源，本机克隆在 `~/code/git-project/hermes-agent`，提交 b3c2883809，2026-10-17）与本项目第一轮优化后的版本。
- 方法：按 5 个领域分头只读代码（智能体循环与模型、记忆与知识库、技能 / 子智能体 / MCP、执行命令 / 审批 / 安全、界面 / 配置 / 运维），结论以代码为准；影响较大的几条又在本项目上实测核实（见第 0 节最后）。
- 写法：Hermes 的位置写成 `H/路径:行号`，本项目写成 `O/路径:行号`。
- 2026-10-23 补记：2026-10-22 前端界面优化（需求池 R37）做完后，有 10 处只做了前端、后端没跟上，统计在第 6 节；正文里相关的地方加了"2026-10-22 进展"注。其余内容仍是 2026-10-20 的状态。

## 0. 一页结论

**两者定位不同。** Hermes 是面向大量用户的通用智能体：同一个内核跑在命令行、20 多个聊天平台、终端界面、桌面应用上，自己写智能体循环，直连约 40 家模型服务商，靠插件和技能扩展，强调"跨会话越用越会"。本项目是单人本机的网页助理：deepagents 加本机 LiteLLM 网关，数据统一在 PostgreSQL，强在知识库与可视化管理。Hermes 的代码量和复杂度高出一个数量级（只 MCP 一块就约 1.1 万行，更新系统 40 个文件），很多健壮性是为"装在成千上万台不同机器上"付出的。

**Hermes 明显做得好、值得借鉴的**（成本低的放前面）：

1. 提示缓存（第 2.2 节）：会话内系统提示词一个字都不变，Claude 也打缓存标记。
2. 出错时先重试、再换备用模型，只在还没输出时重试（第 2.1 节）。
3. MCP 的健壮性：断线自动重连、挂起后定时再试、连续失败暂停调用（第 2.8 节）。
4. 会话全文搜索，界面和智能体都能用，不调模型、返回原文（第 2.5 节）。
5. "插话"不打断正在跑的任务（第 2.1 节）。
6. 一批小而实用的做法：输出截断保留开头和结尾、整文件覆盖前检查是否读过最新版、记忆写成陈述句并在写入前查注入、常驻信息有上限、压缩时逐字保留用户原话。

**本项目明显做得好的：**

1. 文档知识库：上传、切块、混合检索（向量 + 中文分词）、回答带出处可点开。Hermes 核心里没有向量检索和出处。
2. 审批：按会话档位、执行命令必问、MCP 默认先问、能改参数和回复一句话、暂停状态存数据库能扛重启。Hermes 默认只拦"命中危险规则"的命令，MCP 默认全放行，审批靠线程阻塞等待、扛不过重启。
3. 执行隔离：每个会话一个目录、uid 1000、环境变量白名单。Hermes 默认在本机直接执行、环境变量用黑名单。
4. 断线续看不限时（从运行开头整段重放）；设置逐项显示来源和"重启后生效"；用量按每次调用记录；备份不带密钥、恢复前自动备份、有格式版本；类型检查与依赖方向检查更严。
5. 模型接入只有一个出口（网关），复杂度低得多。

**实测确认的本项目问题**（这次对比顺带发现，都已在本机核实）：

| 问题 | 实测 | 影响 |
|---|---|---|
| Claude 完全没有命中提示缓存 | 用量表：claude-opus-4-6 共 123 次调用、114 万输入 token，缓存读写都是 0；gemini 自动命中约 41% | 每次都按全价重发整段历史 |
| 相关记忆每次运行都拼到系统提示词末尾 | `O/agents/main_agent/runtime/knowledge.py:153-174` | 就算开了缓存，换一轮记忆就让后面整段历史的缓存失效 |
| MCP 断线后工具悄悄消失，状态仍是"已连接" | `O/agents/main_agent/integrations/mcp_adapters.py:136-148`：断线时只记日志，工具清空，状态不改、不重连 | 页面看着正常，智能体却用不了那个服务，只能手动"重新加载" |
| 子智能体继承全部工具，包括写记忆的 `remember` | 子智能体定义没写 `tools`，deepagents 默认继承（`deepagents/graph.py:787`） | 数据分析员可能往长期记忆里写东西 |
| 执行的命令能读备份、能写 `.workdata/config/` | 以 uid 1000 实测：`backups/` 能列出、里面的文件可读；`config/mcp_servers.yaml` 可读；`config/` 可写 | 需求池 R33 已登记。在"跳过所有审批"档下，一条被注入的命令能改审批规则、加 MCP 服务、读到全部对话的备份 |

## 1. 总体定位与架构

| 方面 | Hermes | 本项目 |
|---|---|---|
| 入口 | 命令行、20 多个聊天平台、终端界面、Electron 桌面、网页仪表盘 | 只有网页（127.0.0.1:8000） |
| 智能体循环 | 自己写的同步循环，分阶段（`H/agent/conversation_loop.py`） | deepagents（LangGraph） |
| 模型接入 | 约 40 家服务商插件、5 种调用协议、凭据池 | 全部经本机 LiteLLM 网关，上游是公司网关 |

| 扩展方式 | 插件、技能、MCP，"核心保持窄" | 可替换接口 + 配置选择实现；技能、MCP |
| 规模 | 数千个文件，大量文件拆成"门面 + 兄弟文件" | 单仓库，三大块单向依赖 |

## 2. 逐项对比

### 2.1 对话循环、停止与出错

| | Hermes | 本项目 |
|---|---|---|
| 一批工具调用 | 只读工具可并行，读写同一路径的按顺序（`H/agent/tool_dispatch_helpers.py:28-49,212-258`） | LangGraph 工具节点全部并发，不判断冲突 |
| 用户中途干预 | 停止、插话（等当前工具做完后作为用户消息送达，不打断）、纠正（只取消当前这次请求）（`H/agent/interrupt_control.py`） | 只有停止 |
| 停止后 | 已输出的文字存档并标"已中断"；没开始的工具补"已跳过" | 已输出部分 + "已中断、原因、怎么继续"写进存档，说"继续"接着做 |
| 卡死 | 180 秒无数据就断开重连，上下文大时放宽到 240 / 300 秒；连续 5 次才报错；另有整轮 600 秒看门狗 | 固定 120 秒，超时就放弃本次调用 |
| 出错 | 约 28 类错误分类；换同服务商的另一个密钥 → 重试 3 次（5 秒起翻倍到 120 秒）→ 备用模型链，下一轮自动切回 → 失败；已输出过文字就不重试 | 不重试、没有备用模型；额度用完单独识别并提示 |
| 限流与额度的区分 | 429 带额度字样且没有"稍后重试"才算额度用完；也认 `terminal_quota_exhausted`、"hard billing limit" | 402、关键字、排除频率限制字样（整体审查后已修） |

- **借鉴**：
  - 重试和备用模型交给本机网关的配置（`num_retries`、`fallbacks`、冷却），不用写代码；先用 `make smoke` 验证只在开始输出前重试。换了备用模型要在页脚看得出来。
  - 插话：RunManager 收下插话，用一个中间件在下一次调用模型前追加成用户消息。
  - 卡死时限按上下文大小放宽；还没输出任何文字就卡死时自动重试一次。
  - 额度识别补上 `terminal_quota_exhausted`、"hard billing limit"。
- **我们更好**：停止后告诉模型"已中断、怎么继续"，Hermes 没有这句说明。
- **不必做**：同一批工具的冲突判断，个人场景风险低。
- **2026-10-22 进展**：报错卡片有了"重试这一句""换个模型再试""复制详情"，但都是前端拼出来的：重试是把那句话当新消息再发一次；后端只给一段报错文字、没有错误类型，前端只认得"额度用完"（见第 6 节）。

### 2.2 上下文压缩与提示缓存

| | Hermes | 本项目 |
|---|---|---|
| 压缩时机 | 名义 50%，上下文小于 512K 的模型实际抬到 75%（`H/agent/context_compressor.py:1151,2761`） | deepagents 自带：85% 触发，保留最近 10%，旧历史转存成文件 |
| 怎么压 | 先把旧工具输出换成占位（不调模型）；保留开头和最近一段；中间用辅助模型生成结构化摘要；用户原话逐字保留；正则抽出路径、报错、网址做"锚点索引"；再次压缩时更新上次的摘要 | 一次性模型摘要 |
| 提示缓存 | 4 个缓存断点（系统提示 + 最近 3 条），经 LiteLLM 调 Claude 也会打标记；会话内系统提示一个字都不变，记忆写入、新装插件都推迟到下个会话；唯一例外是压缩 | 实际没有缓存：deepagents 的缓存中间件只认 Anthropic 原生客户端，ChatLiteLLM 被跳过；相关记忆每次运行重拼进系统提示词 |

- **借鉴（这一块收益最大）**：
  - 给 Claude 打缓存标记：在网关的模型参数里配 `cache_control_injection_points`，或写一个小中间件。先用 `make smoke` 验证公司网关会转发；用量明细里已经记缓存读写，效果能直接看到。
  - 把相关记忆从系统提示词挪到本轮的用户消息里（只进给模型的存档，界面历史不变；"资料"标记照旧）。常驻条目留在系统提示词里，一个会话内不变。这会修订 D17 里"放在哪"的部分，要你拍板。
  - 压缩摘要的提示里加"用户原话逐字保留 + 锚点索引"；压缩前先跑一次记忆提取，免得被压掉的信息丢失。
- **不改变"只显示 token"的决定**：缓存命中本来就在用量明细里。

### 2.3 模型接入与用量

| | Hermes | 本项目 |
|---|---|---|
| 接入 | 约 40 家服务商插件，订阅账号登录，凭据池；选贵模型要确认 | 一个网关出口；模型页增删改，存网关数据库 |
| 中途换模型 | `/model` 默认只影响本会话，可只管下一轮或写进全局；切换时重算缓存策略与压缩阈值 | 模型存在会话上，下一条消息生效，历史照样带着 |
| 辅助任务 | 压缩、标题等可各配便宜模型 | 跟随会话所选模型（M3 的决定） |
| 用量 | 统一成 5 类 token；价格按服务商自报 → 内置价目 → 公开价格库，标"实际 / 估算 / 套餐内 / 未知"；按会话累加，按会话开始时间归日 | 每次调用一行，按调用方区分；只算 token（D23、第一轮优化 4.11） |

- **评价**：我们把多家接入整体交给网关，更适合单人场景；用量按调用记录比 Hermes 按会话开始时间归日更准。
- **可借鉴**：用量页加"工具、技能各用了几次"。辅助任务用便宜模型与 M3 的决定冲突，只作备选。

### 2.4 记忆与知识库

| | Hermes | 本项目 |
|---|---|---|
| 记忆存储 | 两个纯文本文件：`MEMORY.md`（上限 2200 字符）、`USER.md`（用户画像，1375 字符）；超限时报错，让模型自己删短 | PostgreSQL 知识条目，常驻条目当画像，没有上限 |
| 读写 | 一个 `memory` 工具（新增 / 按唯一子串替换 / 删除），内容整份在提示词里，不用检索 | `remember`、`search_knowledge`、`read_document`；没有"忘掉 / 更正" |
| 什么时候写 | 模型自己写；连续 10 轮没写就在后台起一个复盘分身重放整段对话决定存什么 | 每次运行后后台提取一轮对话，对照相近记忆增、改、删 |
| 进提示词 | 会话开始读一次、冻结；外部召回追加到当轮用户消息 | 每次运行：常驻全部 + 召回最多 5 条，拼进系统提示词 |
| 插件 | 记忆插件接口（预取、同步、压缩前抢救等），默认只用内置 | 一个接口一种实现（pgvector） |
| 文档 / 向量检索 | 核心里没有；靠 `read_file` 整篇读、网页抓取、技能（llm-wiki 等）、第三方插件 | 上传、切块、混合检索、出处引用 |
| 防注入 | 写入和加载时正则扫描（只有英文规则），命中的在提示词里换成占位、原文留给用户删；网页、浏览器、MCP 结果包"不可信数据"标记 | D17"资料"声明 + 尖括号转全角，不依赖语言 |

- **借鉴**：
  - 常驻条目加字数上限，并把"已用 / 上限"告诉模型。
  - 提取提示词加一句"写成陈述事实，不写成命令"（命令式条目以后会被当成指令）。
  - 记忆写入前加一道中英文可疑模式检查；可疑条目在提示词里屏蔽、界面上保留并提示。
  - 补"更正 / 忘掉"工具，按唯一子串定位条目。
  - 网页抓取、MCP 工具的结果逐条包上"资料"标记（现在只有系统提示词里一条总规则）。
- **我们更好**：文档知识库、混合检索、出处、中文分词明显领先；每次运行就提取，比 Hermes 每 10 轮复盘一次更及时也更省。Hermes 那 65 个记忆插件的生态、llm-wiki 方向都不适合我们（后者已决定不做）。

### 2.5 会话存储与检索

| | Hermes | 本项目 |
|---|---|---|
| 存储 | SQLite 一张消息表同时供界面和模型（带"给模型的版本"字段）；系统提示词按哈希存 | 会话表 + LangGraph 存档（给模型）+ 界面历史，分开存（D07） |
| 检索 | 三套全文索引（含中日韩两字切分）；`session_search` 工具四种用法（按词查、前后翻看、读整段、浏览最近），不调模型、返回原文；界面也能搜；提示词里写"用户提到以前的事先搜再问" | 不能检索 |

- **借鉴（这一块最值得补）**：我们已有 PostgreSQL 全文检索和 jieba 分词，对界面历史建索引即可：会话列表加搜索框；加一个 `search_conversations` 工具，返回原文片段与会话链接，能前后翻看。不需要模型总结。
- **2026-10-22 进展**：会话列表加了"搜索会话标题"，但只是前端按标题过滤，对话内容搜不到；后端全文检索和 `search_conversations` 工具都还没做（见第 6 节）。

### 2.6 技能

| | Hermes | 本项目 |
|---|---|---|
| 格式与加载 | SKILL.md，兼容 agentskills.io；系统提示词放"名字 + 说明"索引，`skill_view` 取全文 | 同样的格式与逐步展开（deepagents 技能中间件） |
| 存放与启停 | 四层目录按优先级；全局停用、按平台停用、按操作系统或"当前有没有某工具"决定进不进索引；自带 58 个，按哈希同步、不覆盖用户的修改 | `.workdata/skills/` 一处；页面上传、停用、删除 |
| 自建与维护 | `skill_manage` 工具让智能体新建、局部修改技能；每 10 轮工具调用后台复盘一次；curator 定期把久不用的自建技能标过期、归档；默认写入不审批 | 智能体不能自建（R29 待做） |
| 市场 | 9 个来源，安装前隔离扫描，按"来源信任级 × 扫描结论"放行或拦截 | 没有（R22 待定） |

- **借鉴（做 R29 时）**：用"暂存 → 用户确认"（等于 Hermes 打开 `write_approval`）；修改技能只用"旧文本 → 新文本"的局部替换；自建技能记下来源与最后使用时间，方便以后清理。上传时提示 description 别太长。
- **不建议**：后台自动复盘写技能（每次约 3 万 token，默认不审批容易写进低质量技能）。

### 2.7 子智能体

| | Hermes | 本项目 |
|---|---|---|
| 形式 | 一个 `delegate_task`，主智能体现写目标；传数组就并行，默认最多 10 个 | 通用助手 + 预先定义的"数据分析员"，同步等结果 |
| 隔离与权限 | 全新对话、独立终端、不带记忆；工具只能收窄；永远去掉委派、问用户、记忆、发消息、定时任务；不能再派子智能体 | 继承主智能体全部工具（含 `remember`）；审批与主智能体共用 |
| 结果 | 只回摘要，超长部分写文件；顶层委派后台运行，可查看、纠偏、停止 | 子智能体的最终回答回到主对话 |
| 审批 | 子智能体不能问人，危险命令默认自动拒绝 | 审批卡片照样弹给用户 |

- **借鉴**：子智能体去掉 `remember`；回报限长，超出部分写进工作目录；主提示词加一句"子智能体说成功只是自述，对外有影响的操作要自己核验"。
- **我们更好**：审批真正弹给用户，比一律拒绝更合适。

### 2.8 MCP

| | Hermes | 本项目 |
|---|---|---|
| 配置 | config.yaml 的 `mcp_servers`；`${VAR}` 从 .env 替换，远程服务缺变量就不连；命令行加令牌自动存成 `MCP_<名字>_API_KEY` 并去掉多余的 "Bearer "；支持 OAuth；stdio 子进程环境变量白名单 | `.workdata/config/mcp_servers.yaml`；`${VAR}` 替换，缺的记进 `missing_env` 在页面说明 |
| 健壮性 | 首次连接重试 3 次，断线重连 5 次（退避到 60 秒），之后挂起每 5 分钟再试；连续 3 次失败暂停 60 秒并告诉模型别重试；工具列表变化自动刷新；可延迟到第一次调用才启动 | 启动时后台连接；断线后工具清空、状态仍显示"已连接"、不重连 |
| 工具与审批 | `include` / `exclude` 通配过滤；默认完全信任、不审批，只有标 `untrusted` 的服务才问 | 按工具"自动 / 先问"，通配，默认先问，声明只读的自动 |
| 其他 | sampling 默认开（限每分钟 10 次）；启动 npx / uvx 包前查恶意包库；65 个官方审核的服务目录 | 没有目录（第一轮优化删掉了） |
| 工具太多时 | `tool_search`：MCP 和冷门工具不发完整定义，换成"搜索 / 查说明 / 代为调用"三个桥接工具加一份短清单（默认开） | 每次都发全部工具定义 |

- **借鉴（按优先级）**：
  1. 断线自动重连 + 挂起后定时再试，断线时状态如实显示（现在是个实际缺陷）。
  2. 连续失败暂停调用，并告诉模型不要重试。
  3. 粘贴令牌时去掉多余的 "Bearer "。
  4. MCP 工具定义总量超过阈值时改用延迟加载。
- **我们更好**：审批默认先问、按工具细分，比 Hermes 默认全放行更稳。sampling 默认开不要学。
- **2026-10-22 进展**：MCP 页每行有了状态点（已连接 · N 个工具 / 连接中… / 没有连上 / 已停用），但状态照搬后端；断线缺陷没修，断线后会显示绿点加"0 个工具"（见第 6 节）。

### 2.9 执行命令与文件

| | Hermes | 本项目 |
|---|---|---|
| 执行环境 | 默认本机直接执行（超时 180 秒）；另有 docker、ssh、modal 等后端；docker 默认所有会话共用一个容器 | 后端容器里、每个会话一个目录、uid 1000、ulimit |

| 杀进程 | 进程组 TERM → 1 秒后 KILL；事先给子孙进程拍快照，脱离进程组的也按 PID 补杀，并防 PID 被复用 | 进程组整组杀；脱离进程组的只是"不再等它" |

  - 输出截断改成"开头 + 结尾"（报错和测试汇总常在最后），成本最低。
  - 杀进程前给子孙进程拍快照、按 PID 补杀。
  - 整文件覆盖前检查是否读过最新版。
  - 不能看图的模型先把图片转成描述；上传 PDF、DOCX 时提示用已装的 markitdown 提取文字。
- **我们更好**：会话目录 + uid 1000 + 环境变量白名单，比 Hermes 默认的本机直跑更收敛；文件卡片和预览面板比写标记可靠。
- **2026-10-22 进展**：界面上执行命令显示了退出码，但它是前端从输出末尾那行文字里解析出来的；后端没把 deepagents 给的退出码单独传出来，错误输出并在普通输出里，退出码不是 0 时工具状态仍是"成功"。推给界面的工具输出（约 2000 字）截断时现在会留下末尾的退出码那一行；给模型的截断（约 3 万字、只留开头）没改（见第 6 节）。

| | Hermes | 本项目 |
|---|---|---|
| 信任模型 | 唯一的安全边界是操作系统级隔离；审批、打码、规则都只是辅助（`H/SECURITY.md:60-65,259-263`） | D23：删除全部本机防护，承认任意网页可能调本机接口 |
