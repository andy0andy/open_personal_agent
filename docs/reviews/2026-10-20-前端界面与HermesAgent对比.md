# 前端界面对比：个人智能体与 Hermes Agent（2026-10-20）

- 对比对象：
  - Hermes 有两套界面：网页仪表盘（`web/`，管理页为主）和桌面应用（`apps/desktop/`，Electron + React + assistant-ui，原生对话界面）。提交 b3c2883809。
  - 本项目是第一轮优化后的网页界面（React 19 + Vite + Tailwind 4 + assistant-ui）。
- 依据：
  - 本项目：用 Playwright 在本机 Chrome 上对 8000 只读截图。宽屏 1440×900 拍了深色、浅色两套，另拍了 1024 宽和手机宽 390 各一张。只打开页面，没有改任何数据。
  - Hermes：读界面代码（主题色、字号、圆角都取自代码里的数值），加上仓库里现成的仪表盘截图（`website/static/img/dashboard/`、`docs/dashboard-models/`）。
  - Hermes 的界面没有实际运行：桌面应用的依赖没装全，运行还要读写 `~/.hermes`。
- 范围：只比两边都有的界面（对话、会话列表、模型、技能、MCP、设置、用量），最后给本项目的优化建议。技术栈不变。
- 前提：本项目的配色当初就参考了 Hermes 仪表盘的默认主题（Hermes Teal）。两个底色 `#041c1c` / `#ffe6cb` 一样，`color-mix` 推出其余颜色的比例也一样（卡片 4%、边框 15% 等）。所以这份对比主要是看它在这套配色之上又做了什么，而不是换一套风格。

## 0. 一页结论

**三套界面的风格定位：**

| | Hermes 仪表盘 | Hermes 桌面应用 | 本项目 |
|---|---|---|---|
| 气质 | 复古终端档案风：全大写、宽字距，超宽 / 超窄 / 像素衬线几种展示字体，直角，按钮带斜面立体感 | 类似代码编辑器的高密度工具：正文 13px、工具行 11px、圆角 2～5px，GitHub 式配色，12 套主题 | 仪表盘的墨绿奶油配色 + 普通阅读排版（正文 15px，系统中文字体） |
| 长处 | 辨识度强，"单色 + 状态色"很克制 | 对话流降噪做得极好，审批、报错、运行中输入的交互细致 | 中文阅读舒适，结构化卡片清楚，管理页信息完整 |
| 短处 | 小字对比度低；管理页一半是写死的英文；导航 18 项不分组 | 体量巨大（界面代码约 15 万行）；字太小、全局去掉焦点框 | 两套视觉语言混用；浅色模式提示色看不清；对话流里过程信息太吵；状态信号少 |

**本项目最该改的 5 件事**（第 6 节有完整清单）：

1. **浅色模式的提示色和次要文字对比度不够**（实测数据见第 5.2 节）：
   - 警告黄 1.56:1、成功绿 1.63:1、危险红 3.57:1、次要文字 3.88:1；
   - 后果是品牌图标、"默认"标签、"完成"对勾、审批图标都看不清；
   - 原因是这几个提示色深浅两种模式共用一个值，而这个值是按深色背景挑的。
2. **两套视觉语言混在一起**：
   - 对话、知识库、用量是圆角卡片；模型、技能、MCP、设置是直角方框、等宽小标题、方形开关（照搬了仪表盘风）；
   - 页头有 3 种写法、4 种高度，内容区有 3 种宽度。
3. **对话流里过程信息太吵**：
   - 已经同意的审批仍是一张大卡片，标题还写着"需要你确认"；
   - 同一次命令既有工具卡又有审批卡；
   - 工具名直接显示英文 `execute`；
   - 消息之间的间距忽大忽小。
4. **状态信号少**：
   - 会话列表看不出哪个在跑、哪个在等审批；
   - MCP"已连接"没有颜色点，文字还折成两行；
   - 出错时没有"下一步"按钮。
5. **键盘与无障碍**：只有 1 个文件用了 `focus-visible`，15 处 `outline-none` 去掉了焦点框；不处理"减少动效"。

**Hermes 最值得借的 8 个做法：**

1. 工具过程降噪：工具行标题写成"已运行命令"这样的动词短语；连续多个工具合并成一句摘要；静止时淡化。
2. 审批卡分层：主按钮"运行 ↵"、拒绝 Esc；放宽的选项收进下拉，并要二次确认写明影响范围。
3. 会话状态点：琥珀色是等你处理，主色是在跑，绿色是跑完没看。
4. 报错卡按错误类型给出下一步按钮（重试、换模型、新会话、复制详情）。
5. 待办清单放在输入框上方显示"进度 3/7"，不放在消息流里。
6. 代码块：超长折叠、悬停才出现复制按钮、流式输出时不着色。
7. "何时生效"写清楚；加载失败用常驻的错误卡片加重试按钮，不用转眼就消失的提示条。
8. 两色推导之外，再给每个模式单独设定提示色；系统开启"减少动效"时，把动画压到几乎为零。

**不要学**：全大写宽字距加多套展示字体；13px 以下的小字和 2px 圆角；18 项不分组的导航；"简洁 / 高级"模式这类会翻倍维护成本的开关。

## 1. 整体框架：布局、导航、页头

| | Hermes 仪表盘 | Hermes 桌面 | 本项目 |
|---|---|---|---|
| 分栏 | 侧栏 256px（可收到 56px）+ 内容 | 可拖拽窗格：会话侧栏 237px \| 对话 \| 右侧审查 / 文件 / 终端，⌘B / ⌘J 开关 | 导航 180px + 会话列表 225px（可收起）+ 对话；文件面板在右侧 |
| 导航 | 18 项平铺、全大写，当前项左缘 1px 竖线 | 侧栏就是会话列表，功能入口在命令面板（⌘K） | 两组（工作 / 管理）7 项，当前项浅底 + 左竖线 |
| 页头 | 每页 56px 标题栏，标题后和最右各有一个插槽，页面往里放时间范围、计数、搜索、主按钮 | 34px 窗口栏，标题放在标签页上 | 三种写法：知识库 / 用量是"图标 + 标题"；模型 / 技能 / MCP / 设置是"标题 + 等宽统计 + 右侧按钮"；对话页只有会话标题。高度 46～55px 不等 |
| 内容宽度 | 不限宽，左右留白 24px | 对话列居中 | 对话约 675px；知识库 675px；用量、模型等约 795px |
| 窄屏 | 小于 1024 宽时侧栏变抽屉 | 不超过 640 宽时侧栏变悬停浮层 | 没有适配：390 宽时整屏只剩导航与会话列表，看不到对话；1024 宽时左两栏占去 40% |

**建议：**
- **页头统一成一个组件**：固定 52px，左边"标题 + 一行次要信息"，右边是操作区。对话页也用它：左边会话标题，右边放本会话的权限档位和模型（与工具条同步），以及"更多"菜单（改名、导出、删除）。
- **内容宽度统一成两档**：阅读类（对话、知识库）720px；管理类 880px。
- **窄屏**：小于 1280 宽时导航收成只有图标的窄栏（56px）；小于 768 宽时会话列表变抽屉。现在只绑本机，手机用不上，所以优先级低，但窄窗口分屏时有用。

## 2. 对话界面

### 2.1 会话列表

| | Hermes 桌面 | 本项目 |
|---|---|---|
| 每行内容 | 状态点 + 标题 13px + 相对时间（5m / 3h / 2d），悬停时时间换成 ⋯ | 对话图标 + 标题 |
| 状态 | 6px 状态点：琥珀 = 等你处理，主色实心 + 流动光边 = 运行中，绿 = 已完成未读 | 没有 |
| 分组 | 置顶；按日期（今天 / 昨天 / 本周，凌晨 4 点换天） | 手动拖动排序 |
| 搜索 | 本地即时 + 200ms 后查服务端全文 | 没有 |
| 操作 | 右键菜单十几项，删除红色并二次确认 | 改名、删除 |

**建议：**
- **加状态点**：等审批（琥珀）、运行中（主色）、出错（红）。后端会话列表接口多带一个字段即可。
- **加相对时间**：悬停时换成 ⋯。
- **搜索**：先做纯前端的标题过滤，全文搜索见功能对比报告。
- 会话多了以后再加日期分组。

### 2.2 消息

| | Hermes 桌面 | 本项目 |
|---|---|---|
| 用户消息 | 整宽、1px 细描边、无头像；超过 4 行渐隐，点击可编辑 | 右对齐实心气泡：深色模式奶油底深字，浅色模式深绿底白字，视觉很重 |
| 助手消息 | 无气泡；一轮结束后才出现操作条（复制、重新生成…）和耗时 | 无气泡；每轮下方常驻页脚：耗时、输入、输出、复制 |
| 代码块 | 无标题栏；超过约 121px 折叠，展开最高 40% 屏高；悬停才出现复制；流式时不着色；用 Shiki 着色，浅色注释专门调深 | 有复制按钮；按语言着色（主题色混合） |
| 长会话导航 | 右边缘时间线刻度：每条用户消息一根，悬停预览、点击跳转 | 没有 |

**建议：**
- **用户气泡改轻**：底色改为"强调底色"（主色混 11%）加 1px 边框，文字用正文色。这样不再是全页最抢眼的元素，深浅两种模式观感也一致。保留右对齐，这是中文聊天的习惯。
- **页脚默认淡化**：不透明度 0.6，悬停这一轮时恢复。耗时、输入、输出的顺序不变。
- **代码块**：超过约 16 行折叠，显示"展开 N 行"；流式输出时不着色，结束后再着色，避免闪烁。
- 消息之间的间距统一：同一轮内 12px，轮与轮之间 28px。

### 2.3 思考过程与"正在做什么"

| | Hermes 桌面 | 本项目 |
|---|---|---|
| 思考 | 一行灰字："思考中"带计时，结束后显示"思考了 12s"；进行中在 10rem 小窗里滚动预览；结束后不自动折叠，避免页面跳动 | "思考过程"折叠行 |
| 第一个字出来前 | 小方块动画 + 计时 | 有加载提示 |
| 状态提示 | 静默超过 2 秒才出现"正在读取 / 正在运行…"，已有工具行在跑时不重复提示；带 `aria-live` | 没有单独的提示行 |

**建议：**
- 思考行显示用时，例如"思考了 12 秒"。
- 加一条状态提示行：静默超过 2 秒才出现，内容取自当前工具，例如"正在执行命令… 8 秒"，并带 `aria-live`。

### 2.4 工具卡片

| | Hermes 桌面 | 本项目 |
|---|---|---|
| 标题 | 图标 + 动词短语（"已运行命令""已读取文件"），有中文翻译；成功时不加图标，失败标红 | 工具英文名（`execute`）+ 右侧"✓ 完成" |
| 连续多个工具 | 合并成一句摘要："查看了 3 个文件，运行了 5 条命令" | 一个工具一张卡 |
| 静止时 | 不透明度 0.67，悬停恢复 | 与正文同等醒目 |
| 命令 | "$ 命令"（$ 用主色）、退出码徽标（0 绿、非 0 琥珀）、stdout / stderr 分块、耗时 | 展开后显示参数 JSON 与结果 |
| 子智能体 | 每个子任务一行：状态、目标、模型·耗时 | 有展示 |
| 待办 | 放在输入框上方的状态区，显示"任务 3/7" | 在消息流里 |

**建议（这一块收益最大）：**
- **工具中文名表**：例如 execute → "执行命令"，read_file → "读取文件"，write_file → "写入文件"，search_knowledge → "检索知识库"，remember → "记住"，MCP 工具显示成"files · 写入文件"。标题后面跟一句摘要，例如命令本身（截到 60 字）、文件名、检索词。
- **执行命令的展开内容**：
  - 显示 `$ date +%Y-%m-%d`；
  - 显示退出码徽标；
  - 先显示输出，再显示错误输出；
  - 显示耗时；
  - 不再显示参数 JSON。
- **合并连续工具**：同一轮内连续的工具调用合并成一行摘要，点开再看明细。静止时淡化。
- 待办清单移到输入框上方，显示"进度 3/7"，可以展开。

### 2.5 审批卡片

| | Hermes 桌面 | 本项目 |
|---|---|---|
| 位置 | 消息流末尾，最宽 xl | 消息流中，占满对话列宽 |
| 多条待审批 | 显示"1/3"，后面叠一张缩小的影子卡 | 每个操作逐项选择，选完自动提交 |
| 按钮 | 拒绝（文字按钮）· 始终允许…▾（本会话 / 始终）· 运行 ↵（主色） | 同意、修改后执行、拒绝、回复一句话 |
| 放宽权限 | "始终允许"要二次确认，红色按钮，写明"会写进 config.yaml，以后所有会话都不再询问" | 档位在工具条上选 |
| 快捷键 | Enter 运行，Esc 拒绝；输入框有字时不抢这两个键 | 没有 |
| 处理完以后 | 卡片消失，变成工具行 | 仍是一张大卡片，标题写着"需要你确认"，底部小字"已同意" |

**建议：**
- **处理完的审批收成一行**，并入对应的工具行。例如"已同意 · 执行命令 date +%Y-%m-%d"；拒绝的显示"已拒绝 · …"，用危险色小字。
- **等待中的审批卡**：
  - 标题写"要执行这条命令吗？"，命令用等宽字体单独显示。
  - 按钮从右到左排：同意（主按钮，Enter）、修改后执行、回复一句话、拒绝（文字按钮，Esc）。
  - 卡片用琥珀色左边条，不要整圈黄框。
- **改档位的二次确认**：工具条上把档位切到"跳过所有审批"时弹一次确认，写明"这个会话里的命令和外部工具都不再询问"。
- 我们的"修改后执行""回复一句话"是 Hermes 没有的长处，保留。

### 2.6 输入框与工具条

| | Hermes 桌面 | 本项目 |
|---|---|---|
| 编辑 | 自己写的编辑器，26～150px 自动增高；占位语从 7 句里随机选 | assistant-ui 输入框 |
| 附件 | 拖放、粘贴图片，"+"菜单；粘贴超过 3000 字自动转成附件 | 回形针、拖放 |
| 运行中再输入 | 发送键随状态变：空时是停止，有字时按设置"改向 / 插话 / 排队"；排队的消息可以改 | 运行中只能停止 |
| 草稿 | 按会话存在浏览器本地，会话丢了会迁到新会话并提示可撤销 | 切换会话就丢 |
| 下方信息 | 模型、推理强度两个胶囊按钮 | 权限档位、会话累计 token、模型、文件 |

**建议：**
- **草稿按会话保存**：存浏览器本地，400ms 防抖。
- **支持粘贴截图**。
- 工具条上的"37.6k token"加一个占上下文的百分比：模型信息里已有最大输入长度，悬停时显示明细。
- "跳过所有审批"的红色胶囊保留，这个警示是对的。
- 等以后做了插话功能，发送键再随状态变化。

### 2.7 报错、空状态、提示

| | Hermes | 本项目 |
|---|---|---|
| 报错 | 助手消息里一张红卡（7% 红底、35% 红边），按约 30 种错误给出下一步按钮：重试、换模型、压缩对话、新会话、复制详情 | 文字说明，没有按钮 |
| 加载失败 | 常驻错误卡 + 重试 | 文字 |
| 通知 | 需要操作的放在顶部居中、不自动消失；普通确认放右下、5 秒消失 | 少量行内提示 |
| 新会话 | 大号字标 + 随机介绍语（有中文版 75 句） | 机器人图标 + "从会话列表选择会话，或新建一个会话"，页面上没有输入框 |

**建议：**
- **报错卡加按钮**："重试这一句"、"换个模型再试"（展开模型列表）、"复制详情"。额度用完时只给"换模型"和"复制详情"。
- **空状态直接放输入框**，第一次发送时才建会话（功能梳理 P2 第 15 条），下面放 3 个最近会话。

## 3. 管理页面

| 页面 | Hermes 仪表盘的长处 | 本项目现状 | 建议 |
|---|---|---|---|
| 模型 | 模型卡上有"设为…▾"，能直接指定主模型或某个辅助任务；能力标签分色（工具绿、看图蓝、推理紫）；选择器对话框带模糊搜索，左边按提供商分组；切到贵模型要确认 | 一张"默认模型"卡 + 列表；能力标签（思考 / 看图 / 工具）全是同色描边小框；"默认"是黄色描边，浅色下看不清 | 能力标签用三种语义色的淡底；"默认"改成主色实心小徽章；"测试"按钮旁注明会花几个 token |
| 技能 | 左侧过滤栏带计数；行内开关；悬停才出现编辑；装之前能看源码、做安全扫描，按信任等级着色 | 结构相似（左侧全部 / 已启用 / 已停用带计数）；开关是方形的 | 开关统一成圆角胶囊样式；描述两行截断，悬停看全文 |
| MCP | 传输方式徽章分色（http 绿、stdio 黄）；测试结果直接写在行下（成功绿字列出工具名，失败红字显示错误）；启停后提示"重启后生效" | "已连接 14 个工具"折成两行、没有状态色；开关是方形的 | 状态用彩色点加文字（已连接绿、连接中蓝、失败红、停用灰）；测试结果写在行下；传输方式徽章分色 |

### 4.2 本项目的对比度实测

数值是 WCAG 对比度。正文要至少 4.5，大字和图标要至少 3。

| 颜色 | 深色模式 | 浅色模式 |
|---|---|---|
| 正文 | 14.67 | 11.56 |
| 次要文字 | 6.23 | **3.88** |
| 警告黄 `#ffbd38`（品牌图标、"默认"标签、审批图标） | 10.60 | **1.56** |
| 成功绿 `#4ade80`（"完成"对勾） | 10.14 | **1.63** |
| 危险红 `#fb2c36`（"跳过所有审批"） | 4.64 | **3.57** |
| 边框 | 1.48 | 1.31 |

结论：深色模式基本没问题；浅色模式的提示色和次要文字都要按模式单独设定。卡片之间的边框淡一些没关系，但输入框的边框太淡，看不出哪里能输入。

### 4.3 配色建议

保留"两个底色推导其余颜色"的做法，以及现在的墨绿和奶油两个底色，这是我们的辨识度。在这个基础上改五处：

1. **提示色按模式区分**：
   - 浅色改成更深的同色系，都在背景上算过对比度：
     - 琥珀 `#b45309`（4.70）
     - 成功 `#1f7a4d`（4.98）
     - 危险 `#b42318`（6.16）
     - 新增"运行中"蓝 `#1d5fa8`（6.04）
   - 深色保留琥珀 `#ffbd38` 和成功 `#4ade80`；危险提亮到 `#ff5a5f`（5.79）；新增"运行中"蓝 `#6aa7f0`（7.07）。
2. **次要文字**：浅色的混合比例从 62% 提到 70%（约 4.8）；深色保持 62%。
3. **输入框边框单独一个变量**：深浅都混 35%（深色 2.85、浅色 1.99），聚焦时换成主色。卡片之间的分隔线保持 15%。
4. **提示色的淡底**：琥珀、成功、危险、运行中各有一个"淡底"，用 10% 混入背景，供徽章、审批卡左边条、报错卡底色使用。不再出现"黄色描边小框"。
5. **用量图表的系列色**也走变量：输入用主色 70%，输出用成功色。

写法示意（只改 `frontend/src/styles/tokens.css` 与 `themes/default.ts`，组件仍只用语义样式类）：

```css
:root {                      /* 深色 */
  --theme-danger: #ff5a5f;
  --theme-info: #6aa7f0;
  --muted-ratio: 62%;
}
:root[data-mode="light"] {
  --theme-warning: #b45309;
  --theme-success: #1f7a4d;
  --theme-danger: #b42318;
  --theme-info: #1d5fa8;
  --muted-ratio: 70%;
}
@theme inline {
  --color-muted-foreground: color-mix(in srgb, var(--theme-primary) var(--muted-ratio), var(--theme-background));
  --color-input: color-mix(in srgb, var(--theme-primary) 35%, var(--theme-background));
  --color-info: var(--theme-info);
  --color-warning-soft: color-mix(in srgb, var(--theme-warning) 10%, var(--theme-background));
  /* success-soft、danger-soft、info-soft 同理 */
}
```

### 4.4 风格建议：统一成一套"安静的墨绿奶油"

- **一套圆角**：所有卡片、面板、输入框、按钮都用主题圆角（8px），徽章用 6px，状态点和开关用全圆。管理页去掉直角方框，与对话页一致。
- **等宽字体只给数据**：模型名、命令、路径、设置键、数字统计用等宽。区块标题（"我的 MCP 服务""对话与模型"）改回正文字体，字号 13px、中等粗细、次要文字色。不用全大写、不加宽字距。
- **按钮三级**：
  - 主按钮：主色实心，每页最多一个，如"新增模型""上传技能"；
  - 次按钮：1px 输入框边框加透明底；
  - 文字按钮：危险操作用危险色文字。
  - 去掉现在"奶油实心直角块"的样式。
- **开关**：改成圆角胶囊样式，开着时用主色底。
- **字号层级**：
  - 页标题 17px；
  - 区块标题 13px；
  - 正文 15px（不变）；
  - 次要说明 13px；
  - 徽章和页脚 12px；
  - 不用 11px 以下。
- **间距尺度**：4 / 8 / 12 / 16 / 24 / 32px。卡片内边距 16px，区块之间 24px。
- **品牌**："PERSONAL AGENT"等宽大写字标保留，这是唯一的风格点缀；浅色模式下图标改用琥珀 `#b45309`。顶部那层淡淡的暖光也保留。
- **焦点与动效**：
  - 全局加可见的焦点框：`focus-visible` 时 2px 主色 45% 的外框，偏移 2px；
  - 系统开启"减少动效"时，把过渡和动画压到几乎为零；
  - 过渡时长统一：控件 120ms，面板 200ms。

## 5. 不建议照搬

- 仪表盘的全大写、宽字距、超宽 / 像素展示字体、斜面按钮：辨识度强，但中文排版不好看，长时间看也累。
- 桌面应用的 13px 正文、11px 工具行、2px 圆角：单人日常阅读，舒适比密度重要。
- 12 套主题、导入 VS Code 主题、自定义 YAML 主题、"简洁 / 高级"两种模式：维护成本翻倍，我们深浅两套够用。
- 可拖拽的多窗格布局、命令面板、71 个快捷键：等真有需要再做。
- 配置页按默认配置自动生成表单：说明文字会变成键名的翻版。我们的设置项少，手写说明更好。
