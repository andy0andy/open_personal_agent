# 第二轮第四批「运维与技能」 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 一条命令体检全部服务；恢复备份后数据变少会提醒；`.workdata` 的配置文件有格式版本、能按版本迁移；代码复杂度有上限；依赖有 3 天冷却期；测试不碰真实密钥、不靠固定等待；技能页显示最近使用时间、上传时提示说明别太长。

**Architecture:** 体检是宿主机上跑的 Python 脚本（`deploy/doctor.py`，只用标准库，命令与网络请求可注入，单测不碰容器）。恢复对比在 `deploy/restore.sh` 里用 psql 数两次。配置版本由 `config/` 定义当前版本与读取规则、`backend/settings/` 在启动写默认文件之前迁移。复杂度上限进 ruff 与 eslint 规则，超标的几个函数按职责拆小、行为不变。测试卫生在根 `conftest.py`（清凭据、不读 `.env`）与一条扫描测试里落地。技能的最近使用时间取自第三批的 `tool_usage`。

**Tech Stack:** Python 3.12 标准库（subprocess、urllib、json）、bash 3.2、PostgreSQL、uv 0.11.7（`exclude-newer` 相对时长）、pnpm 11.17（`minimumReleaseAge`）、ruff（C901、PLR0915）、eslint（complexity、max-statements）、vitest 假时钟。

**Spec:** `docs/specs/2026-10-23-optimization-round2-design.md` 第 7 节（7.1～7.7），以及第 9 节约束

## Global Constraints

- 不新增依赖；依赖方向 `backend → agents → config → common`，backend 只用 agents 各模块 `__init__.py` 公开的内容。
- 项目没有 git：不执行 git；台账 `.superpowers/sdd/2026-10-23-round2-batch4/progress.md`。不读、不打印 `.env`。
- 自动化测试只用测试库、临时目录、假模型；不调用真实模型。改了接口在同一任务里 `make types`。
- 固定取值与文案（设计 7.x，原样使用）：
  - 体检：逐项 `✓` / `✗`，`✗` 后写怎么修；不打印任何密钥；模型列表经后端 `/api/models` 取，不用网关的 `/health`（会真的调用每个模型）。
  - 恢复提醒："会话 A→B、消息 C→D，比恢复前少；不是你想要的就用 pre-restore-… 退回"（消息数按 `runs` 行数）；库里没有这些表时跳过。
  - 配置版本：`mcp_servers.yaml`、`approval_rules.yaml`、`skills.yaml` 写 `version: 1`；没有版本号当作 0；迁移前复制到 `.workdata/config/history/<文件名>.<时间>.bak`。
  - 复杂度：ruff `C901`（`max-complexity = 20`）与 `PLR0915`（默认 50）；eslint `complexity: 20`、`max-statements: 50`；都在 `make check` 里。
  - 冷却期：`[tool.uv] exclude-newer = "3 days"`（锁文件只多 `[options]` 两行，版本不变）；`frontend/pnpm-workspace.yaml`：`minimumReleaseAge: 4320`、`saveExact: true`；Dockerfile 复制它。
  - 测试：清掉 `*_KEY`、`*_TOKEN`、`*_SECRET`、`*_PASSWORD` 环境变量（`-m live` 除外），构造设置时不读 `.env`；测试代码里 `sleep(非 0)` 必须同一行注明"允许等待：原因"。
  - 技能说明：超过 300 字提示"说明尽量短"，超过 1024 字提示"会被截断"（deepagents 只读前 1024 字）。
- 前端单测写作 `WEB vitest <文件>`，Python 单测写作 `PY <文件>`。

## Review Focus

1. 体检遇到服务没起、后端没在跑、网关连不上、请求超时：每项都打 `✗` 并说怎么修，不卡住、不崩、不打印令牌与密钥（任务 8 的 `test_doctor_*`）。
2. 配置迁移遇到手改过的文件（带注释、写坏的 YAML、空文件）：不毁掉用户内容；先备份再改；写坏的不动、启动不失败（任务 7）。
3. 恢复对比：库里没有 `threads` / `runs`、数量相同或变多时不误报；litellm 库照常（任务 9）。
4. 拆函数只改结构不改行为：靠现有测试兜底，`make check`、`make test-int`、`make e2e` 全过（任务 5、6）。
5. 清凭据不能弄坏 `make smoke`（`-m live`），也不能让测试悄悄读到 `.env`（任务 2）。
