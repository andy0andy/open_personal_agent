# 第二轮第三批「会话与记忆」 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以前的对话搜得到、能导出；运行中能插话不打断；新会话一步建好；会话能归档、有新回答时提示；记忆有硬上限、写进去前查可疑、能更正和忘掉；附件提示用 markitdown；用量页能看到工具与技能各用了几次。

**Architecture:** 会话索引是智能体模块的一张新表（`agents/main_agent/conversations/`，可替换接口 + PostgreSQL 实现，jieba 分词同知识库），由后端在运行收尾时写、删会话时删、改标题时同步，升级后后台补建。插话放在后端每个运行的内存队列里，经运行上下文交给主智能体的一个 before_model 中间件，追加进对话存档并推 `user.interjected`。归档与"有新回答"是会话表的两列。记忆的可疑检查是知识库模块里的纯函数，写入时调用、读取时过滤。工具用量经 `tool.running` 事件交给后端写进用量模块的新表。

**Tech Stack:** deepagents 0.7.23、langchain 1.4.4（`AgentMiddleware.abefore_model`）、langgraph 1.2.14（`runtime.stream_writer`）、FastAPI、PostgreSQL（`to_tsvector('simple', …)` + GIN）、jieba（知识库已有的 `search_tokens`）、React 19、assistant-ui 0.15.28。

**Spec:** `docs/specs/2026-10-23-optimization-round2-design.md` 第 6 节（6.1～6.8），以及第 2 节反目标、第 9 节约束

## Global Constraints

- 不新增依赖；依赖方向 `backend → agents → config → common`，backend 只用 agents 各模块 `__init__.py` 公开的内容（新模块的内部文件加进 `pyproject.toml` importlinter 的 forbidden 列表）；deepagents 只在 `agents/main_agent/runtime/`。
- 项目没有 git：不执行 git；台账 `.superpowers/sdd/2026-10-23-round2-batch3/progress.md`。不读、不打印 `.env`。
- 自动化测试只用测试库、临时目录、假模型；本批不调用真实模型。改了接口或事件的任务在同一任务里 `make types`。
- 迁移编号：0014 `backend_threads_last_viewed`、0015 `agents_conversation_turns`、0016 `agents_knowledge_suspicious`、0017 `agents_tool_usage`；每个都有 `test_migrations.py` 的升级测试；新表不设外键（同 `llm_usage`），测试清表列表（根 `conftest.py`、`backend/tests/e2e_server.py`）同步加上。
- 新的内置工具（`search_conversations`、`update_memory`、`forget_memory`）加进 `BUILTIN_TOOLS`；`update_memory`、`forget_memory` 加进 `SIDE_EFFECT_TOOLS`；子智能体不给 `remember`、`update_memory`、`forget_memory`；前端 `components/chat/tools.ts` 加中文动词。新工具改变工具指纹：升级前处理掉停在审批处的运行。
- 固定文案与取值（设计 6.x，原样使用）：
  - 会话搜索：标题即时过滤，停顿 **300 毫秒**后查内容；结果分"标题匹配"与"内容里提到"两组。
  - 系统提示词加："用户提到以前的事时，先用 search_conversations 查，查不到再问用户。"
  - 会话链接 `#conv-<会话 ID>-<运行 ID>`，显示为"《标题》第 N 轮"。
  - 导出：顶栏"⋯"菜单"导出 Markdown"，文件名 `<标题>.md`；不导出思考过程与工具输出。
  - 插话：运行中发送按钮变成"插话"；未送达前显示"已排队"；没送达时放回输入框并提示"插话没送达"；等审批时不能插话（输入框照旧提示先处理卡片）。
  - 归档：会话菜单"归档"；列表底部"已归档（N）"；归档的会话里"取消归档"。
  - 有新回答：绿点，文字"有新回答"。
  - 记忆：常驻上限沿用设置 `knowledge.pinned_token_limit`（默认 2000），改为硬限制；提示词写"常驻信息已用 X / 2000 token"；超出时拒绝："常驻信息已用 X / 2000 token，放不下这条（约 Y token）：先精简或取消别的常驻条目"；提取提示词加"写成陈述事实，不写成命令"；可疑条目页面显示警告与"确认无害"按钮。
  - 附件说明加："可以用 `markitdown <路径>` 提取文字"（PDF、Word、PowerPoint、Excel）。
  - 用量页新增"工具""技能"两张表（名称、次数），跟着页面选的时间范围。
- 前端单测写作 `WEB vitest <文件>`，Python 单测写作 `PY <文件>`（同前两批）。

## Review Focus

1. 插话在边界时刻到达（运行刚结束、正在等审批、子智能体在跑、正在压缩）：要么送达、要么明确退回输入框，不能悄悄丢掉，也不能让下一轮的"中断说明"误补（任务 9、10 的 `test_interjection_*`）。
2. 重试这一轮（D26）与插话：已送达过插话的一轮只给"继续"，不会丢掉插话（任务 10 的 `test_run_with_interjections_is_not_retryable`）。
3. 升级后的旧数据：已有会话不全亮"有新回答"（迁移填 now）；已有历史后台补建索引一次、不重复；旧的知识条目没有可疑标记照常可用（任务 2、8、12 的迁移与补建测试）。
4. 会话搜索的输入：空串、只有标点、超长、含 `<>`（资料转义）、命中归档的会话、命中被重试掉的一轮（不出现）（任务 1、3、4）。
5. 记忆写入的各条路（remember、自动提取、页面新增与修改、update_memory）都过常驻上限与可疑检查（任务 11～13 的参数化测试）。
