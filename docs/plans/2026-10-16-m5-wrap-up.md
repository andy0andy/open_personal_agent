# M5 收尾 实施计划

> **给执行者：** 必须使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐个任务执行本计划。步骤用复选框（`- [ ]`）跟踪。开始任何任务前先读 `.claude/skills/dev-standards/SKILL.md`。
>
> 本计划只写定下来的决定：文件、名称与签名、取值、每个任务用哪些测试证明。函数体由执行者按签名与测试写出；只有签名和测试决定不了的规则才在计划里写明。

**目标：** 第一版收尾——用量能按天、按模型版本、按会话统计，数据能一键备份与恢复，主要流程有自动的浏览器测试，使用指南完整，并逐条核对设计文档 1.3 节的成功标准。

- **用量统计**：
  - 新增用量统计页（侧栏"用量"），可选最近 7 / 30 / 90 天；
  - 按天看输入、输出、缓存与费用的趋势，按模型版本、按调用方（主智能体、子智能体、标题、记忆整理、上下文压缩、向量化）、按会话拆分。
- **网关核对**：调用网关时带上会话与运行编号，在 LiteLLM 后台的日志里能按会话、运行找到每一次调用（设计文档 7.1）。
- **向量化计入用量**：向量化调用也记进用量表（设计文档 7.7）；本机模型不花钱，但次数和 token 能统计到。
- **备份**：
  - `make backup` 一键备份两个数据库和 `workdata/` 里的个人文件，放在 `workdata/backups/`，保留最近 7 份；
  - `make restore BACKUP=<名字>` 恢复，恢复前自动先备份一次当前数据。
  - 只做手动备份（2026-10-16 与用户确认，不做定时备份）。
- **端到端测试**：`make e2e` 用 Playwright 驱动本机的 Chrome（用户选定，不另下载浏览器），后端接按剧本回复的假模型，覆盖发消息、工具卡片、审批、下载产物、运行中刷新、停止、用量页、设置页。
- **使用指南**：`docs/usage.md` 写全安装、启动、配置模型版本与 MCP、日常使用、备份恢复，README 只留快速开始并指向它。
- **成功标准核对**：逐条记下证据，写成 `docs/decisions/M5-成功标准核对.md`。

需求池的待定项本期不并入（2026-10-16 用户确认）。

**架构：**

- **调用归属**：`agents.main_agent.models` 新增与网关无关的 `call_context(thread_id, run_id)`，一个上下文变量。
  - 智能体的每段运行、标题生成、记忆提取都在它里面进行。
  - LiteLLM 网关的实现在每次请求时读它，给请求加上 `litellm_session_id` 与 `metadata.tags`。
  - LangGraph 在运行里新建的任务会复制上下文变量，所以子智能体、上下文压缩的调用也带得上。
- **向量化用量**：向量化实现在每次请求后调用组装根注入的回调。回调写入用量表，调用方为 `embedding`，所属会话与运行取自 `call_context`；文档入库时为空。
- **用量汇总**：`UsageRepo.summary` 只查 `llm_usage`；会话标题由 backend 用 `ThreadRepo` 补上（数据归属：智能体不查 backend 的表）。按天分组用浏览器传来的时区。
- **备份恢复**：`deploy/backup.sh`、`deploy/restore.sh` 两个脚本。
  - 用 `pg_dump -Fc` / `pg_restore --clean` 经 `compose exec -T` 在数据库容器里执行，文件用 tar。
  - 数据库容器、库名、目录都由环境变量指定，集成测试指向测试库与临时目录。
- **端到端**：
  - `backend/tests/e2e_server.py` 组装真实的 backend：测试库里单独的 `agent_e2e` 库、临时工作区；假模型 `KeywordChatModel` 按最后一条用户消息里的关键词选剧本；还有一个先问你的假 MCP 工具。
  - 前端打包结果由它直接提供，Playwright 用 `channel: "chrome"`。

**技术栈：**

- 新增前端开发依赖 `@playwright/test@1.63.0`：最新的 1.64 发布不满两周。安装时设 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`，不下载它自带的浏览器。
- 新增 Python 依赖：无。
- 用量页的趋势图用 CSS 柱条，不引入图表库。

## 重点关注

1. **按天统计用用户所在的时区**：北京时间凌晨 0:30 的调用（UTC 前一天 16:30）算在北京时间的当天；没有调用的日子显示为 0，不缺天。测试：
   - 任务 3 `test_summary_groups_days_in_the_given_timezone`；
   - 任务 4 `fillDays`。
2. **费用未知**（模型没有登记价格）：
   - 全部未知时费用显示"—"，不显示 0；
   - 部分未知时只加已知的部分，并提示哪些模型没有价格；
   - 已删除的会话的用量仍计入，标为"已删除的会话"。
   - 测试：任务 3 `test_summary_with_unknown_costs`、`test_summary_endpoint_adds_titles`。
3. **恢复时选错**：
   - 备份名字打错、备份不完整（缺文件）：拒绝并说明，不动现有数据；
   - 恢复前自动备份当前数据，选错了还能退回。
   - 测试：任务 5 `test_restore_refuses_missing_or_incomplete_backup`、`test_restore_backs_up_current_data_first`。
4. **备份时服务正开着、有对话在跑**：备份照常完成（`pg_dump` 取一致的快照）；只保留最近 7 份，最旧的自动删掉，备份目录不会越积越多。测试：任务 5 `test_backup_keeps_only_the_latest`。
5. **端到端测试不能碰正式数据、不能花钱**：后端只接受测试库地址，否则拒绝启动；模型是假的，不连网关。测试：任务 6 `test_e2e_server_refuses_a_non_test_database`。

## 先行探测结论（2026-10-16 写计划时实测，脚本在会话临时目录 `m4-probe/`、`pw-probe/`）

| 问题 | 结论 |
|---|---|
| 给网关的请求带上会话与运行 | 经 ChatLiteLLM 时：`metadata`、`tags` 两个参数名与 LangChain 自己的参数冲突（`got multiple values`）；直接传的 `litellm_session_id` 没有转到网关。**用 `extra_body={"litellm_session_id": 会话, "metadata": {"tags": ["thread:…", "run:…"]}}` 有效**：网关库 `LiteLLM_SpendLogs` 的 `session_id` 是会话 ID，`request_tags` 含这两个标签。自定义字段（如 run_id）不会单独存下，所以运行也放进标签 |
| ChatLiteLLM 每次请求的参数 | `_client_params`（属性，每次请求时现算）→ `litellm.acompletion`；只有 `model_kwargs` 会并进去。子类重写 `_client_params` 即可让每次请求都带上，且不影响已有的 `stream_options` 等参数 |
| 向量化返回的用量 | 网关 `/embeddings` 的返回带 `usage.prompt_tokens`（两段 4 token），`completion_tokens` 为 0 |
| Playwright 用本机 Chrome | `@playwright/test@1.63.0`，`PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` 安装（约 19MB），`use: { channel: "chrome", headless: true }` 能打开本项目页面并点击（1.7 秒） |
| 备份与恢复数据库 | `compose exec -T postgres pg_dump -U agent -Fc <库>`，标准输出就是完整的备份文件（开头 `PGDMP`；compose 的提示在标准错误里，不能混进来）。`pg_restore --clean --if-exists --no-owner` 恢复到新库后表与 `vector` 扩展齐全；测试库一次 0.3 秒、约 25KB。正式库有 `agent` 与 `litellm` 两个库 |
| 测试库进容器 | `compose --profile test exec -T postgres-test …` 可用 |

    - `unpriced_models: list[str]`：有调用但费用全为空的模型。
  - `UsageRepo.summary(*, days: int, tz: ZoneInfo, today: date | None = None) -> UsageSummary`：`today` 只供测试固定日期。
- 产出（backend）：
  - `ThreadRepo.titles(ids: Sequence[UUID]) -> dict[UUID, str]`；
  - 接口 `GET /api/usage/summary?days=30&tz=Asia/Shanghai` → `UsageSummaryView`：`UsageSummary` 的字段，`by_thread` 换成 `list[ThreadUsageView]`，在 `ThreadUsageSummary` 上加 `title: str | None`，None 表示已删除的会话。

**规则：**
- 范围：`tz` 时区里的 `today - (days - 1)` 到 `today`。
- 按天分组：`(created_at AT TIME ZONE %(tz)s)::date`，时区名作 SQL 参数，不拼接。
- 费用合计：全部为空 → None；部分为空 → 已知的和。
- 接口参数：
  - `days` 1～365，默认 30；
  - `tz` 默认 `UTC`。不是 IANA 时区名时 422，原因"时区不认识：<值>"。

### 任务 5：备份与恢复

**文件：**

- 修改：`Makefile`（`backup`、`restore` 两个目标，带 `##` 说明，`make help` 里看得到）

**脚本约定**（两个脚本都 `set -euo pipefail`；参数一律来自环境变量，便于测试指向测试库）：

| 变量 | Makefile 里的值 | 含义 |
|---|---|---|
| `PG_EXEC` | `$(DC) exec -T postgres` | 在数据库容器里执行命令的前缀 |
| `PG_USER` | `agent` | |
| `DATABASES` | `agent litellm` | 要备份的库 |
| `WORKDATA` | `workdata` | |
| `FILE_DIRS` | `workspace knowledge shared` | `WORKDATA` 下要打包的目录，不存在的跳过 |
| `BACKUP_ROOT` | `workdata/backups` | |
| `KEEP` | `7` | |

- **backup.sh**：
  1. 建 `<BACKUP_ROOT>/<YYYYmmdd-HHMMSS>/`；
  2. 每个库 `pg_dump -U $PG_USER -Fc <库>` 写成 `<库>.dump`。只取标准输出，标准错误另记 `backup.log`：compose 的提示在标准错误里，混进来会损坏备份；
  3. `tar -czf files.tar.gz -C $WORKDATA <FILE_DIRS 中存在的>`；
  4. 写 `manifest.txt`：时间、库名、目录名；
  5. 只保留最近 `KEEP` 份（按名字排序删最旧的；只删符合时间戳格式的目录）；
  6. 输出备份位置与大小。任何一步失败：删掉这次不完整的目录，退出码非 0，并说明哪一步失败。
- **restore.sh**：
  - 参数 `BACKUP`：备份目录名。
  - 名字不存在或缺文件（manifest 里列的库的 `.dump`、`files.tar.gz`）：说明并退出 1，不动现有数据。
  - 确认：没有 `CONFIRM=yes` 时提示"将用备份 <名字> 覆盖现有的对话、知识库和文件。恢复前会先自动备份当前数据。输入 yes 继续："，从终端读取，不是 yes 就退出。
  - 先调用 backup.sh 备份当前数据（失败就停止）。
  - 每个库：`pg_restore -U $PG_USER --clean --if-exists --no-owner -d <库>`，备份文件经标准输入传入。
  - 删掉 `FILE_DIRS` 现有目录，再解开 `files.tar.gz`。
  - 输出"已恢复，恢复前的数据备份在 <名字>"。
- **Makefile**：
  - `backup`：`$(NEED_ENV)` 后执行 backup.sh；
  - `restore`：没给 `BACKUP` 时列出已有备份并退出；给了时：
    1. 先停 backend 与 litellm（`$(DC) stop backend litellm`）；
    2. 执行 restore.sh；
    3. 再起 litellm 与 backend（`$(DC) up -d --wait litellm` 然后 `$(START_BACKEND)`）。restore.sh 失败时也要把它们起回来。
