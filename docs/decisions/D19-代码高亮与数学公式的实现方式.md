# D19：代码高亮与数学公式的实现方式

- 状态：已采纳（2026-10-16 独立审查后修订第 3、5、6 条）
- 日期：2026-10-16（R13，用户交给我决定，按开发流程执行）

## 背景

设计文档 13.1 要求回答的 Markdown 支持数学公式与代码高亮，13.2 要求代码高亮读主题变量（深浅两版、以后的新主题都不用改组件）。M0～M5 只接了 GitHub 风格 Markdown（表格等），代码块是单色，公式显示成源码。

## 结论

1. **代码高亮用 lowlight（highlight.js 的语法分析，常用的 37 种语言），不用 Shiki。**
   - 同步出结果：回答逐字推送时每来一段都要重新渲染，同步高亮不会先闪一下单色。
   - 输出的是带类名的片段（如 `hljs-keyword`），颜色写在 `styles/markdown.css` 里、从主题变量派生，换深浅色或换主题自动跟着变。
   - Shiki 着色更准，但要异步加载、体积大，它的配色方案是写死颜色的数据，与主题系统对不上。
   - 不在这 37 种里的语言、没写语言的代码块：照原样单色显示。
2. **高亮颜色由主题已有的颜色混合出来，主题文件不加字段。**
   - 关键字、字符串、数字、类型与属性四类颜色由固定色（警告、成功、危险）与主色按比例混合；函数名、类名只加粗不着色；注释用次要文字色。
   - 浅色版混入更多主色：固定色是为深色背景定的，直接用在浅色背景上太淡。
3. **代码块上方加一条标题栏**：语言名与复制按钮。
   - 复制先用浏览器的剪贴板接口；局域网 HTTP 访问时浏览器不提供它（不算安全环境），被拒绝时也一样，这两种情况退回到"隐藏文本框 + 复制命令"，都不行时显示"复制失败"（`components/useCopy.ts`，用量页复制会话 ID 也用它）。
4. **数学公式用 KaTeX**（remark-math 识别、rehype-katex 渲染）。
   - KaTeX 用 0.16 系列，与 rehype-katex 依赖的是同一份；样式文件必须与渲染用的版本一致，否则排版错位。
   - 写错的公式显示原文（危险色），不影响整条回答。
5. **渲染前统一公式写法：以 assistant-ui 自带的两个函数为主，只补它们处理不好的写法**（`components/chat/math.ts`）。
   - 各家模型写法不同：Claude 多用 `$…$`、`$$…$$`，GPT、Gemini 常用 `\(…\)`、`\[…\]`。
   - 框架的 `normalizeMathDelimiters` 把后两种转成 `$` 写法，并带上列表、引用的前缀（公式块留在列表项、引用里，表格不被拆开）；`escapeCurrencyDollars` 把"$5""$19.99"这类金额转义成文字。两者都认得各种代码块（缩进的、引用里的、HTML 块），代码里的内容一律不动。编码规范要求优先用框架能力；我们自己最初写的版本在列表、表格、缩进代码块上都出过错（审查发现）。
   - 先补两种写法（只改代码以外的部分，代码的位置用 Markdown 解析器 mdast-util-from-markdown 找出）：
     - 中文里不带空格的金额："成本是$5，其中变量$x$"，框架会把"5，其中变量"当成公式。规则：`$` 后跟数字，且同一行里没有下一个 `$`、两者之间夹着汉字或全角标点、或下一个 `$` 后紧跟数字，就当金额；已经打开的公式的结尾 `$` 永远不动。
     - `\(…\)` 里写了 `\$`（如算钱的公式）：转成 `$$…$$`，否则遇到 `$` 公式就提前结束、报错。
   - 单独占一行的 `$$…$$` 按公式块显示（一个小的 remark 插件）：框架把单行的 `\[…\]` 转成 `$$…$$`，remark-math 当行内公式排版，分数、积分号会变小。
6. **逐字输出时降低渲染的优先级**（assistant-ui 的 `defer`）：每来一段文字都要重新解析、重新渲染全部公式，公式多时（150 个约 100 毫秒）会卡；降为低优先级后界面忙时跳过中间几次，打字和滚动不受影响，最终的全文总会渲染。

## 范围

只改回答正文（`MarkdownText`）。思考过程仍是纯文字；文件面板里预览代码文件不高亮（不在 R13 内）。

## 代价

- 前端打包体积增加（KaTeX 与 37 种语言的语法规则）：脚本从 883KB 到约 1.33MB（压缩传输从 262KB 到约 400KB）；公式字体另外按需下载。本机使用，加载时间影响很小；以后需要时可改成用到才加载。
- 浅色版的高亮颜色混入 65% 的主色，对比度 4.97～8.86（深色版 4.75～10.17）；颜色偏暗、偏绿，不如深色版鲜明。浅色版注释用的次要文字色在代码块底色上原来只有 3.60；2026-10-22 界面优化把次要文字色加深后已是 5.33（`themes/contrast.test.ts` 守着）。
- highlight.js 的着色比 Shiki 粗，个别语言的细节（如 TypeScript 的类型标注）着色不全。
- 金额与公式的判断是规则，不是理解：少数写法仍会判断错，如 `$5 到 10$` 被当成公式。2026-10-26 修了几种（积压小问题 A12～A16）：正文里的 `\[1\]`、`a\[0\]` 按文字显示；公式块里的 `\\[2pt]` 不再和后面的 `\[…\]` 配对；网址里的 `$数字` 不再被插反斜杠；路径里的环境变量 `$HOME/$USER`（`$` 后 3 个以上大写字母或下划线、紧跟 `/`）按文字显示——代价是 `$ABC/DEF$` 这种写法的公式会被当成文字；`设 $n$2 个` 这种结尾 `$` 后紧跟数字、内容两头不是空白也不夹汉字的按公式显示。做法：要躲开框架处理的字符先换成私用区的占位字符，框架处理完再换回（`components/chat/math.ts`）。另两点代价：`\[…\]` 里只有数字、逗号、连字符（`区间 \[0, 1\]`），或 `\[` 紧挨字母数字（`hence\[x=1\]`）时也按文字显示；原文里本来就有那几个私用区字符（图标字体的码位）时，这一条回答不做上面这些修正，照框架原来的处理（免得换回时把它们也改掉）。Markdown 链接的地址整段跳过、裸网址到 `{` `}` 为止，链接后面同一行的金额照常是文字（审查发现的回退，已修）。
- KaTeX 的结果没有缓存：`defer` 只减少了渲染次数，公式非常多的回答在输出过程中仍会多用一些电脑算力。（2026-10-26 决定仍不做：要新增直接依赖、自写渲染插件。公式里写的尺寸已限在 20em 以内，被注入的超大尺寸撑不出极长的元素。）
