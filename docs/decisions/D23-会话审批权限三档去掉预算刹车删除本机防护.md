# D23：会话审批权限三档、去掉预算刹车、删除本机安全防护

- 状态：已采纳（2026-10-19 用户决定）；第 5 条与"跳过所有审批"被 D25 修订（2026-10-23：加回令牌 + Host 校验，危险命令任何档位都要问）
- 日期：2026-10-19
- 设计：`docs/specs/2026-10-19-optimization-round1-design.md` 第 4.1、4.3、4.4、4.8 节

## 背景

v1 的审批对所有会话一视同仁：执行命令固定先问（D21 第 7 条），外部工具按规则文件。日常用下来审批卡片太多。预算刹车（D18）按调用次数暂停，用处不大。本机安全防护（令牌、局域网、主机名、来源检查、只收 JSON，设计文档 12.2）暂时用不上：以后考虑第三方防护。

## 结论

1. **会话的审批权限三档**（用户决定，参考 Claude Code 的模式选择）：

   | 取值 | 名称 | 行为 |
   |---|---|---|
   | `ask`（新会话默认） | 每次先问 | 执行命令先问；外部工具按审批规则（服务声明只读的自动，其余按 `mcp_default`）；内置的读写会话文件等自动 |
   | `ask_execute` | 只问执行命令 | 只有执行命令先问，其余全部自动（审批规则不看） |
   | `skip` | 跳过所有审批 | 什么都不问，包括执行命令 |

   - 档位存在会话上（`threads.permission_mode`），在输入框下方的工具条里选。
   - **一次运行开始时定下档位，整次运行（含审批后继续）都用它**：档位记进这次运行的 `input`；运行中或等待审批时改档位，从下一条消息起生效。原因：中途改了，"要先问哪些工具"就变了，审批核对（工具指纹）会失效。
   - 智能体按（模型，档位）分别组装、分别缓存；工具指纹也按档位算。
   - "执行命令固定先问"（D21 第 7 条）只在 `skip` 下放开，前两档照旧。
   - MCP 页的审批规则只在 `ask` 档起作用，页面上写明。
2. **去掉预算刹车**（用户决定）：删除 `budget` 设置、暂停与"继续 / 停止"卡片、推送的预算状态、恢复时的预算参数、设置页的预算展示。
3. **模型额度用完时**：这次运行结束，显示"模型额度用完了（模型服务返回余额或配额不足）。已输出的部分已保存，充值后说“继续”接着做。"；不另设暂停状态（充值的时间不确定，挂着一个暂停的运行没有意义）。
   - 判断依据：HTTP 402、`BudgetExceededError`，或报错里有余额不足、配额用完一类的字样（`insufficient_quota`、`credit balance`、`余额不足` 等）。
   - 普通的频率限制（429 rate limit）不算。
4. **任何失败都保留已输出的部分**（同停止，D07 的延伸）：已输出的文字连同一句中断说明写进对话存档，说明写清实际原因（用户停止、模型长时间没有响应、模型额度用完、调用出错）。下一句说"继续"时模型知道写到了哪里。
5. **删除本机安全防护**（用户 2026-10-19 两次确认后接受）：
   - 删除：访问令牌与令牌页、局域网访问（`LISTEN_ADDRESS`）、主机名白名单、写操作来源检查、只收 JSON，以及启动时的配置自检；
   - 端口固定只绑本机 `127.0.0.1:8000`。

## 风险（照录设计 4.8，用户已接受）

删掉以后，**你浏览的任何网页都能在本机执行任意命令，与会话的权限档位无关**：
- 网页能直接调后端接口：把会话档位改成"跳过所有审批"、替你点"同意"（`/runs/{id}/resume`）；
- 更直接的是 MCP 的"添加服务""测试连接"：提交一个本地进程型服务、命令随便写，后端立刻以 root 身份运行，完全不经过审批；
- 主机名检查没了以后，"DNS 重绑定"（让恶意域名指向本机）也能调全部接口；新版 Chrome 访问本机前会先弹窗请求许可，能挡掉一部分，但不能依赖。
- 以后由第三方防护补上。

## 修订关系

- D18：预算刹车部分作废（审批的实现方式仍有效）。
- D20 第 4 条、D21 第 7 条："执行命令固定先问"改为只在前两档成立。
- 设计文档 12.2（本机安全防护）作废。

## 代价

- 每个会话要自己选档位；新会话总是从"每次先问"开始。
- 本机没有任何访问控制，安全完全依赖"只绑本机"与以后的第三方防护。
