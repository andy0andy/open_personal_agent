# D22：配置进数据库与 `.workdata`，去掉"自带 + 用户"的叠加

- 状态：已采纳（2026-10-19 用户决定）
- 日期：2026-10-19
- 设计：`docs/specs/2026-10-19-optimization-round1-design.md` 第 4.7、4.10 节
- 取代：D21 第 1、2、6 条（`workdata/` 叠加 `config/`、叠加规则、备份范围）。D21 第 3 条（模型走网关的模型管理接口）与"上传的技能不许同名"保留。
- 修订（2026-10-26 用户决定，积压小问题 G5）：第 8 条的备份范围加上 `.workdata/.seeded`（启动时补写过哪些默认内容）。恢复时备份里有就整份替换（不合并：它记的是备份时那份数据做过哪些补写），更早的备份没有就不动现有的；这样恢复到新的 `.workdata` 后，删掉的默认技能、模型不会被重新写回。

## 背景

D21 让管理页面把改动写进 `workdata/config/`，加载时与 `config/` 按条目叠加。用下来：配置散在两处，排查时两边都要看；"自带"的条目只能停用不能删；`app.yaml` 里只有默认对话模型能在页面上改。用户要配置只有一个来源。

## 结论

1. **普通设置进数据库**（用户决定）：
   - 原来 `config/app.yaml` 的设置改存 PostgreSQL 的 `app_settings` 表（每个设置键一行，值是 JSON），`config/app.yaml` 删除；
   - 取值顺序：**代码里的默认值 → 数据库 → 同名环境变量（含 `.env`）**，后者覆盖前者。环境变量名是设置键把 `.` 换成 `__` 再大写，如 `AGENT__DEFAULT_MODEL`；
   - 连数据库之前就要知道的（数据库地址、网关地址与密钥、`LITELLM_SALT_KEY`）只在环境变量里，不进数据库；
   - 启动分两步：先按环境变量连上数据库，再读设置表（`load_settings`）。表里某一项不合规（手改坏了）时去掉这一项、记日志，后端照常启动。
2. **设置页**列出全部设置：当前值、来源（默认 / 已改 / 环境变量）、能否在页面上改、改了何时生效。
   - 只有默认对话模型立即生效，其余重启后端生效（`make restart`）；
   - 被环境变量覆盖的项不能在页面上改：改了也不会生效；
   - 向量模型只读（R31）；
   - 模型来源只读：来源里有网关地址，能改就可能把密钥发到别处（我的决定）；
   - 各可替换接口选用的实现只读：目前每项只有一种实现（我的决定）。
3. **后端容器整份读入 `.env`**（`env_file`，我的决定），`.env` 里的同名变量在容器里真的生效。`make restart` 改为重建后端容器（`up --force-recreate`），重启进程读不到新的 `.env`。
   - 网关要用的密钥不进后端（2026-10-20 终审 I2 更正）：上游网关地址与密钥、`LITELLM_SALT_KEY`、各厂商的 `*_API_KEY` 在 compose 里给后端置空（`deploy/tests/test_compose.py` 检查）。原来写的"密钥不外流"不成立：智能体执行的命令确实只拿白名单里的变量（D20），但本地 MCP 服务以 root 跑在后端容器里，能读到后端进程的全部环境变量；MCP 配置里的 `${变量}` 也按后端进程的环境变量替换。所以 `.env` 里给 MCP 用的密钥，所有本地 MCP 服务都看得到；MCP 要用某个厂商的密钥时在 `.env` 里另起一个变量名。
4. **`.workdata/` 是唯一的数据目录**（`workdata` 改名，用户决定）：
   - `config/mcp_servers.yaml`、`config/approval_rules.yaml`、`config/skills.yaml`（停用了哪些技能）；
   - `skills/`（全部技能）；`workspace/`、`knowledge/`、`shared/`、`cache/`、`backups/`；
   - 不再叠加 `config/` 里的文件；"自带"的说法从三个管理页上去掉，全部条目能改、能删。
5. **首次启动写入默认内容**（只补缺的、从不覆盖）：默认文件放在 `config/seed/`（`files` 服务、默认审批规则、`excel` 技能），4 个模型的清单在 `config/seed/models.yaml`，经网关接口导入网关数据库。写过的部分记在 `.workdata/.seeded`（`files`、`models` 各一行），用户删掉的默认项不会被重新写回；网关暂时连不上时，模型下次启动再导入。
6. **模型全部在网关数据库里**：`config/models.yaml` 只留网关自身的设置。
7. **迁移与退回**：
   - 第二批动手前把整个项目（代码、`workdata/`、两个数据库的导出）打包成一份整体快照（`open_personal_agent-snapshots/20261019-before-batch2/`）；
   - 迁移后的代码不恢复迁移前的旧备份：`make restore` 认出旧格式时拒绝并说明原因。
8. **备份保留**（我的决定）：放 `.workdata/backups/`，范围是两个数据库与 `.workdata` 的 `config/`、`skills/`、`workspace/`、`knowledge/`、`shared/`。

## 代价

- 设置的一部分在数据库里：直接看文件看不到，要看设置页或查 `app_settings` 表；备份必须带上数据库（本来就带）。
- 用户删了默认的 MCP 服务、技能后想找回，要自己从 `config/seed/` 复制回 `.workdata/`。
- 被同意的命令仍然改得动 `.workdata/` 里的配置（D21 第 7 条的风险不变，R33）。
