# D26："重试这一轮"从运行前的存档分叉；做过有副作用的操作只能"继续"

- 状态：已采纳
- 日期：2026-10-23
- 设计：`docs/specs/2026-10-23-optimization-round2-design.md` 第 4.5 节

## 背景

- 前端原来的"重试这一句"其实是再发一条同样的消息：对话存档里会有两条一样的用户消息，失败的那一轮也还在，模型会带着它往下做。
- 失败常发生在已经调过几次工具之后：从头重跑时模型看不到那些结果，多半会再做一遍（同一条命令跑两遍、同一条记忆记两遍）。

## 备选方案

1. 再发一条同样的消息（原做法）。
2. 从失败那次运行之前的对话存档分叉重跑。
3. 分叉重跑；但这一轮做过有副作用的操作时不给重试，只给"继续"。

## 结论

采用方案 3：

1. **接口** `POST /api/runs/{id}/retry`：只能用在会话里最近一次、失败或停止的运行上；用同样的原文与附件、会话当前的模型与审批权限发起新运行，新运行记 `retry_of`（迁移 0013）。连点、两个标签页同时点只生效一次。
2. **怎么分叉**：按 `run_id` 找到这次运行最早的存档点，从它的上一个存档点往下跑；会话第一轮就失败时先清掉这个会话的存档；这次运行一个存档点都没留下时照常跑。新运行用新的 `run_id`。
3. **有副作用的调用**：执行命令、写入 / 修改 / 删除文件、记记忆（`remember`）、没声明只读的 MCP 工具；认不出的名字（如 MCP 服务已经不在）也算。按这次运行全部的 `tool.started` 判断（含审批暂停之前那一段、子智能体内部的）；被拒绝而没执行的也算（事件分不出来）。
4. **运行结束事件**带 `error_kind`（`quota / rate_limit / stalled / gateway / context_overflow / interrupted / other`）与 `retryable`。报错卡片按它们给按钮：
   - 额度用完、上下文超长：只能"换个模型"（超长时只列上下文更长的）；
   - 其余：能重试时"重试这一轮"，不能时"继续"（发一句"继续"）；也能"换个模型"——先改会话的模型，再重试或继续；
   - 总能"复制详情"。
5. 界面上，失败的那一轮收成一行"第 N 次失败：原因（已重试）"，后面接新的回答。
6. 进程中途退出（界面历史里没有结束事件）的运行算"被打断"、不能重试，只给"继续"。

## 原因与代价

- 模型看不到失败的那一轮，用户消息只出现一次；做过有副作用的操作时只"继续"，对话存档里有这些调用的结果和中断说明，模型能接着做，同一操作不会做两遍。
- 代价：判断偏保守，少数本可以重试的只给"继续"；失败的那一轮在对话存档里成了一条没人走的分支（不影响之后的对话）。
