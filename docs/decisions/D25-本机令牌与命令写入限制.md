# D25：本机令牌与 Host 校验、命令只能写放行的目录、危险命令的硬底线（修订 D23）

- 状态：已采纳（2026-10-23 用户决定：加回一层轻防护；Landlock 用不了时"先不管"）
- 日期：2026-10-23
- 设计：`docs/specs/2026-10-23-optimization-round2-design.md` 第 5.1、5.2、5.11 节

## 背景

D23 第 5 条删掉了本机安全防护，代价写得很清楚：你浏览的任何网页都能调本机接口、在本机执行命令；主机名不检查以后 DNS 重绑定也能进来。另外两处同样没有底：

- 被同意的命令以 uid 1000 运行，能写到会话目录以外的地方（`.workdata` 里的配置、技能、备份目录也在同一个容器里）；
- "跳过所有审批"档什么都不问，`rm -rf ~`、`curl … | sh` 这类命令也直接执行。

## 结论

1. **本机令牌 + Host 校验**（修订 D23 第 5 条）：
   - 后端每次启动生成一个随机令牌（`secrets.token_urlsafe(32)`），只放在内存里。
   - `GET /api/session` 只校验 Host，返回令牌，同时下发同值的 Cookie `opa_session`（HttpOnly、SameSite=Strict、Path=/）。
   - `/api/` 下除了 `/api/health`（容器健康检查）和 `/api/session`，都要令牌：请求头 `X-Session-Token`；推送、图片、下载这类带不了请求头的 GET / HEAD 也认 Cookie；**写操作只认请求头**。不对返回 401"会话令牌不对或已过期，请刷新页面"。
   - 所有请求（含页面）的 Host 只认 `127.0.0.1`、`localhost`，端口不限（8000、开发用的 5173、端到端测试的 8100），否则 400。
   - 前端先取令牌再发请求；遇到 401 自动重取一次再发；推送被服务器关掉时重取令牌、从最后收到的序号重开一次。所以后端重启（令牌变了）页面不用刷新。
   - 实现是一个纯 ASGI 中间件（`backend/api/local_guard.py`），推送照常流式。
2. **命令只能写放行的目录**（R33）：
   - 后端以 root 运行、命令切到 uid 1000 时，用 `setpriv` 加 Landlock 规则，**只限写入**：本会话目录、`cache/exec-home`（装包缓存）、`/tmp`、`/dev`；读不限。写类权限里含 `refer`（跨目录改名、硬链接）：Landlock 对它默认一律拒绝，不放行的话放行目录之间 `os.rename` 也会失败。补杀与探测用的辅助进程以 uid 1000 运行，只给 `PATH` 一个环境变量（同一用户的命令读得到它们的环境）。
   - 第一次以 uid 1000 运行命令前探测一次内核支不支持；不支持时记一条警告，不加限制（见"代价"）。
   - 后端容器里 `.workdata/backups` 用一个空的只读目录（`deploy/empty-dir`）遮住：命令看不到也改不了备份。备份脚本在宿主机上运行，不受影响。不用内存盘：podman 的 tmpfs 默认会把底下的备份复制进去（升级时实测读得到），关掉它的选项只有 podman 认。
3. **危险命令的硬底线**（修订 D23 第 1 条的"跳过所有审批"）：任何档位，执行命令命中下面任一条都要先问，审批卡片标题前用红字写"危险操作：…"：删除根目录或家目录、删除或改写 `.workdata`、格式化磁盘（mkfs）、直接写磁盘设备（dd of=/dev/…）、关机或重启、下载后直接执行（curl … | sh）、把根目录权限改成 777。判断只看命令文字（恢复审批时再判断一次，结果必须一样）：引号外的换行当作命令分隔，切词去掉引号后逐段看命令名与参数，`cd` 进 `.workdata` 之后的写操作、`bash -c` 里的命令也算；"下载后直接执行"包括 `| sh`、`| python3`（解释器从标准输入读脚本时）、`sh -c "$(curl …)"`、`bash <(curl …)`。

## 代价与防不住的

- **同一容器里的命令和 MCP 进程能直接访问后端**：它们和后端在同一个网络里，带着正确的 Host 就能先取令牌再调接口。令牌只挡得住浏览器里的跨站网页和 DNS 重绑定。
- **Landlock 用不了时**（内核太旧或没启用），命令的写入范围退回到只靠文件权限：uid 1000 能写的地方它都能写。用户决定"先不管"，不加替代办法；当前 podman 虚拟机内核 6.19 支持，已实测。
- 硬底线是按文字匹配的黑名单，绕得过去（如把命令写进脚本再执行）；它只是兜底，挡的是模型一时糊涂，不是恶意。
- 手工调接口要先取令牌：`curl -s http://127.0.0.1:8000/api/session` 拿到 `token`，之后带 `-H "X-Session-Token: <令牌>"`；后端重启后要重取。

## 影响

- D23 第 5 条（删除本机安全防护）被本决定修订：加回的是令牌 + Host 这一层轻防护，不恢复设计文档 12.2 的其余部分（局域网访问、来源检查、只收 JSON 仍然不做）。
- D23 第 1 条的"跳过所有审批"：危险命令照样要问。
- 本地 MCP 服务仍以 root 跑在后端容器里（R36 记着，可与以后的单一容器整理一起做）。
  2026-10-26 补记（积压小问题 E16）：用户决定本地 MCP 服务维持 root 运行，由用户自己把控接入哪些服务，不再改动、也不再作为风险提出。
