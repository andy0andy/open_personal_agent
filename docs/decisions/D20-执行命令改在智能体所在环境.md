## 背景

D08 让智能体的命令在一个常驻的沙箱容器里执行：断网、只读根文件系统、非 root、资源上限，后端经内部 HTTP 把命令发过去。用户不认可这种做法：执行代码、读写文件就应该和智能体在同一个环境；以后会把整个智能体整理成一个独立容器，沙箱不必再单独用容器。

## 结论

1. **命令在智能体所在的环境里执行**（`agents/main_agent/workspace/local_sandbox.py` 的 `LocalSandbox`，替换 `HttpSandbox`）。
   - 用 bash 在会话目录 `<数据目录>/workspace/<会话短 ID>/` 里执行；数据目录即 `WORKDATA_DIR`（默认项目的 `workdata/`），改它就是"指定位置"。
   - 沿用 D08 时的行为：单独成一个进程组，超时（默认 120 秒、最长 600 秒）或运行被停止时连同子进程一起杀掉；输出过长只返回开头一段，完整输出写进会话的 `logs/`。
   - 智能体看到的路径仍是 `/workspace/<会话短 ID>/...`：后端镜像里 `/workspace` 指向工作区目录，脚本里写的绝对路径照样能用；命令输出里的真实路径换回 `/workspace/...`。
2. **与智能体共用同一个 Python 环境**（用户选定）：pandas、numpy、matplotlib 等加进项目依赖；中文字体与 matplotlib 配置放进后端镜像。
3. **删掉容器沙箱**（用户选定）：沙箱镜像、执行服务、`sandbox` / `sandbox-test` 两个容器、内部专用网络与内部密钥 `SANDBOX_SECRET`。"执行命令"仍是可替换接口（`Sandbox`），以后要隔离可以再加一个实现。
4. **执行命令每次先问你**（用户选定）：`config/approval_rules.yaml` 里 `execute: ask`。
5. **不在容器里以后的缓解**：
   - 执行时只传一份白名单里的环境变量（`PATH`、语言、时区等），不传网关密钥、数据库地址等；`HOME` 指向 `workdata/cache/exec-home`（各会话共用）。
   - 智能体以 root 运行时（后端容器里就是），命令改用 uid 1000 执行，并清掉 root 的附加用户组：改不动项目的 Python 环境，也读不到只有 root 能读的文件。
   - 源码与配置（`agents/`、`backend/`、`common/`、`config/`）以只读方式挂进容器：一条被同意的命令改不了代码和审批规则（独立审查发现：原来是可写挂载，Mac 上的共享目录不区分用户）。
   - 命令结束、超时或被停止时杀掉整个进程组；看的是 bash 本身是否退出，不等输出管道关闭。脱离了进程组的后台进程（`setsid` 之类）杀不到：命令照常返回，输出里注明，进程会继续存在。
   - 单个文件大小、进程数用系统的进程限制（`ulimit`）。

## 代价

- 执行的代码可以上网了；能读到 uid 1000 能读的所有文件（项目目录里的大部分文件）；能读写 `workdata/` 里的个人数据（会话文件、知识库原文件、共享文件夹、备份）。只靠"每次先问你"把关。
- 执行的代码和后端在同一个网络里：能连到后端自己的接口（没设 `ACCESS_TOKEN` 时不需要令牌）、数据库（compose 里的默认账号密码，psycopg 就在共用的 Python 环境里）与 Ollama。一条被同意的命令能读写全部对话、记忆与运行状态。可以考虑的缓解（未做）：没设访问令牌时自动生成一个只给后端与浏览器用的令牌；数据库密码改由 `.env` 提供；整理成单一容器时再加网络隔离。
- 所有会话共用执行时的 HOME（`workdata/cache/exec-home`），一个会话写进去的文件别的会话也能读到。
- 没有内存上限（`ulimit -v` 会让 numpy 一类程序起不来）：失控的程序可能占满后端容器的内存。以后整理成单一容器时，在容器上限内存。
- 会话之间互相看不到文件（R16）在同一个用户身份下做不到。
- 只在后端容器里才有 `/workspace` 这个路径；直接在本机跑后端时，脚本里的绝对路径用不了（目前后端总是在容器里跑）。
